## 统一的工程选择

- 产品名称采用 LottoLab；首期 SSQ，DLT 第二期。D07、D09 等扩展彩种提议暂不扩大首期范围。
- 采用 FastAPI + PostgreSQL + React/TypeScript/Vite。D03/D20 的 Vue、D21 的 Streamlit 快速原型、D16 的 Workers/D1 均为备选，不并行维护多套 UI 或数据库。
- 原始文件、规范表、特征和实验结果分层即可；D04/D07 的 TimescaleDB、额外队列/缓存，D17 的大数据与全套随机比特测试只有在证明需要后才引入。
- 先 Uniform/Frequency 和严格回测，再上线线性与树模型。LSTM、Transformer、生成模型和奖池/销量预测属于后续实验，不阻挡基础平台。
- D01 是早期多模型意见汇总，D02 是共同出题模板，不能作为权威规则或实验结果；D13 含导出聊天标记和引用占位，外部来源需重新核验。
- 把各文档的“七天计划”转成 PLAN.md 的阶段与退出条件，保留进度和失败恢复信息，不强迫用户管理每个阶段。
- 统计、回测、UI、Docker 和 CI 在相应实现阶段实际验证。只生成配置文件不等于测试或上线通过。

## 实现前仍要核实

官方来源和使用条件、各彩种现行/历史规则、完整期次与休市日历、浮动派奖数据、依赖版本兼容性。每个模块实现前阅读对应来源完整章节，结合本规格验证；有冲突时记录依据并修正规格，不盲信任何一份方案。

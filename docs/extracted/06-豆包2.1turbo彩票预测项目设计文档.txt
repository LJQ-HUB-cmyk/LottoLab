# 彩票预测项目科学实现方案 — 项目设计文档

> 版本 v1.0 | 角色：高级数据工程师 / 机器学习工程师 | 状态：可直接进入开发

---

## 1. 项目背景

国内彩票（双色球、大乐透、3D、排列三等）每期公开开奖结果，历史数据可回溯 20 年以上。民间存在大量"预测大师""AI 选号"产品，绝大多数基于伪科学（热号、冷号、遗漏值外推），无统计效度。

真实痛点分三层：
- **彩民**：需要一个不忽悠、能解释"为什么选这组号"的工具。
- **数据从业者**：彩票是绝佳的"iid 均匀分布"教学案例，可用于展示特征工程、回测、模型对比的完整工程链路。
- **合规产品**：市场缺少明确声明"不保证中奖"、以期望值（EV）优化为核心的理性选号工具。

本项目不做"预测下一期开奖号"，而做**基于公开数据的统计分析 + 期望值最优选号 + 严格回测**的工程平台。

---

## 2. 项目真实目标

| 层级 | 目标 | 可量化指标 |
|---|---|---|
| L1 数据层 | 构建多彩种历史开奖数据管道，自动更新 | 数据延迟 ≤ 开奖后 30min，覆盖率 100% |
| L2 分析层 | 提供分布检验、频率/遗漏/奇偶等描述性统计 | χ² 均匀性检验 p 值可查，所有指标可复算 |
| L3 选号层 | **期望值最优选号**：在均匀随机前提下，最小化"与他人撞号导致奖金被平分"的概率 | 单注期望奖金相对机选提升 ≥ 5%（基于历史中奖分布回测） |
| L4 回测层 | Walk-forward 回测 + Monte Carlo 模拟，验证任何策略相对随机基线无显著超额收益 | 回测框架可复现，p 值透明 |
| L5 合规层 | 全链路免责声明、理性购彩引导、未成年人拦截 | 免责声明在选号结果页强制展示 |

**核心声明**：开奖号是 iid 均匀随机变量，任何模型都无法在公平彩票中获得超越随机的命中率。本项目的"智能"体现在**选号组合的期望值优化**，而非预测开奖结果。

## 3. 彩票预测是否可行的统计学解释

### 3.1 数学事实

以双色球为例：红球从 33 个中选 6 个（不重复、无序），蓝球从 16 个中选 1 个。

- 头奖概率：1 / C(33,6) × 16 = 1 / 17,721,088 ≈ 5.64 × 10⁻⁸
- 每期开奖独立同分布（iid），历史结果不影响未来结果。

### 3.2 为什么机器学习无法预测

| 论点 | 说明 |
|---|---|
| 目标变量是均匀噪声 | 每个球在每期被开出的条件概率恒为 6/33（红）或 1/16（蓝），与历史无关。模型学到的任何"模式"都是过拟合。 |
| 无信号可提取 | 特征与目标的互信息 I(X;Y) ≈ 0。任何非零 AUC 都在随机波动区间内。 |
| 赌徒谬误 | "冷号该出了"是典型谬误；回归均值不意味着补偿性出现。 |
| 样本量不足 | 双色球历史约 3000 期，相对 1772 万种组合，覆盖率 0.017%，不足以学到联合分布。 |

### 3.3 唯一可利用的低效性：Pari-mutuel 平分风险

彩票奖金池是**彩民共享**的（pari-mutuel）。头奖奖金 = 奖池 / 中奖注数。

- 如果选了"热门号"（如生日号 1-31、连号、等差数列），中奖后更可能与多人平分，单注奖金降低。
- 选"冷门号"不提高中奖概率，但**提高中奖后的单注金额**，从而提高期望值 EV。
- 这是本项目唯一真实的"α"来源，且可量化、可回测。

### 3.4 期望值公式

```
EV(单注) = P(中奖) × E[奖金 | 中奖]
         = P(中奖) × Σ_k P(该注与 k 人同时中奖) × (奖池 / (k+1))
```

热门号使 k 增大，EV 降低。选号优化的目标即最小化 E[k]。

## 6. 数据清洗规则

```python
# cleaning_pipeline.py 核心规则伪代码

def clean_raw_record(record: dict, lottery_code: str) -> dict:
    """单条原始记录清洗，返回清洗后 dict 或 None（丢弃）"""

    # R1 字段完整性：必填字段非空
    required = ["draw_period", "draw_date", "red_balls"]
    if any(not record.get(f) for f in required):
        return None  # 丢弃并记日志

    # R2 期号格式校验：YYYYNNN，年份合理
    if not re.match(r"^\d{7}$", record["draw_period"]):
        return None
    year = int(record["draw_period"][:4])
    if not (2000 <= year <= current_year()):
        return None

    # R3 号码范围与数量校验（按彩种配置）
    cfg = LOTTERY_CONFIG[lottery_code]
    red = sorted(record["red_balls"])
    if len(red) != cfg["red_count"]:
        return None
    if not all(cfg["red_min"] <= n <= cfg["red_max"] for n in red):
        return None
    if len(set(red)) != len(red):  # 不重复
        return None

    # R4 蓝球校验（如有）
    if cfg["blue_count"] > 0:
        blue = sorted(record["blue_balls"])
        if len(blue) != cfg["blue_count"]:
            return None
        if not all(cfg["blue_min"] <= n <= cfg["blue_max"] for n in blue):
            return None

    # R5 日期与期号一致性：期号年份 == 开奖日期年份
    if record["draw_date"].year != year:
        return None

    # R6 去重：同一 lottery_code + draw_period 已存在则跳过（UPSERT）
    # R7 金额字段：负数置 NaN，超阈值（>1e12）标记异常
    # R8 双源交叉校验：若两源同一条记录号码不一致，标记 conflict 并人工复核
    # R9 时序连续性：按期号排序，检查缺失期，记录 gap 报告
    # R10 编码统一：全角→半角，中文数字→阿拉伯数字，去除空格/不可见字符

    return {
        "lottery_code": lottery_code,
        "draw_period": record["draw_period"],
        "draw_date": record["draw_date"],
        "red_balls": red,
        "blue_balls": blue if cfg["blue_count"] > 0 else [],
        "sales_amount": record.get("sales_amount"),
        "jackpot_pool": record.get("jackpot_pool"),
    }
```

**清洗质量门**：
- 入库前记录数 vs 原始数，丢弃率 > 5% 触发告警。
- 每期开奖后 30 分钟内必须入库，否则告警。
- 每周生成数据质量报告：缺失期数、异常金额、冲突记录数。

## 7. 特征工程清单

> 重要声明：以下特征均为**描述性统计特征**，用于数据洞察和"热门号预测"子任务。它们**不具备预测开奖号的能力**，任何将其用于"预测下一期开奖"的模型都会过拟合。

### 7.1 单号码特征（每个球号 × 每期）

| 特征名 | 计算方式 | 类型 |
|---|---|---|
| `freq_30` | 近 30 期出现次数 | 计数 |
| `freq_100` | 近 100 期出现次数 | 计数 |
| `freq_all` | 历史总出现次数 | 计数 |
| `gap_current` | 当前遗漏期数（距上次出现） | 计数 |
| `gap_max` | 历史最大遗漏 | 计数 |
| `gap_avg` | 历史平均遗漏 | 浮点 |
| `hit_rate_30` | 近 30 期出现频率 | 浮点 |
| `deviation_from_expected` | 实际出现次数 - 理论期望次数（n × p） | 浮点 |
| `popularity_score` | 来自 number_popularity 表 | 浮点 |

### 7.2 组合特征（一注号码的整体特征）

| 特征名 | 计算方式 | 说明 |
|---|---|---|
| `sum_val` | 红球和 | 双色球理论范围 21-183 |
| `span_val` | 最大红球 - 最小红球 | |
| `odd_count` | 奇数个数 | |
| `even_count` | 偶数个数 | |
| `prime_count` | 质数个数 | |
| `big_count` | 大号（>17）个数 | 以中位为界 |
| `consecutive_count` | 连号组数（如 5,6 算一组） | |
| `ac_value` | 算术复杂性 AC 值 | 彩票分析常用指标 |
| `zone_dist` | 三区分布比（1-11/12-22/23-33） | 三元组 |
| `tail_dist` | 尾数分布（0-9 各出现几次） | 十维向量 |
| `mod3_dist` | 除 3 余数分布 | 三元组 |
| `avg_popularity` | 该注所有球的 popularity_score 均值 | **EV 优化核心特征** |
| `max_popularity` | 该注中最热球的热度分 | |
| `birthday_overlap` | 与生日号区间（1-31）重叠数 | 热门代理特征 |

### 7.3 时序特征（仅用于热门号预测模型）

| 特征名 | 说明 |
|---|---|
| `popularity_lag_1` | 上一期热度分 |
| `popularity_ma_7` | 近 7 期热度移动平均 |
| `popularity_trend` | 近 10 期线性回归斜率 |
| `jackpot_pool_lag_1` | 上期奖池金额（奖池大→投注多→热度分布变化） |
| `day_of_week` | 开奖日星期几（周二/四/日，购买行为有差异） |

## 8. 模型方案对比

### 8.1 模型总览

| 模型 | 用途 | 输入特征 | 预期表现 | 是否采用 |
|---|---|---|---|---|
| **Random Baseline** | 随机机选，基线 | 无 | 命中率 = 理论概率，EV = 理论 EV | ✅ 基线必备 |
| **Frequency (Hot/Cold)** | 热号/冷号策略 | freq_30, gap_current | 命中率与随机无显著差异（χ² 检验 p>0.05） | ✅ 用于展示"无效" |
| **Markov Chain** | 状态转移概率 | 上期号码→本期 | 转移矩阵收敛到均匀，无预测力 | ✅ 用于学术对比 |
| **XGBoost 分类器** | 预测每个球是否开出 | 全部 7.1 特征 | AUC ≈ 0.5（随机），log_loss 无改善 | ✅ 证明 ML 无效 |
| **LSTM / Transformer** | 时序预测开奖号 | 历史序列 | 过拟合严重，样本外 AUC ≈ 0.5 | ❌ 不采用（算力浪费） |
| **热门号预测模型（XGBoost 回归）** | 预测每个号码的 popularity_score | 7.1 + 7.3 特征 | RMSE 可降低，用于 EV 优化 | ✅ **核心采用** |
| **组合优化器（整数规划 / 模拟退火）** | 从候选球中选最优组合 | avg_popularity 最小化 + 约束 | 生成低热度组合，EV 提升 | ✅ **核心采用** |

### 8.3 核心模型二：组合优化器

```python
# optimizer.py
import numpy as np
from scipy.optimize import dual_annealing

def select_combination(popularity_scores: np.ndarray,
                       red_count: int = 6,
                       red_range: int = 33,
                       constraints: dict = None) -> list:
    """
    目标：最小化选中球的 avg_popularity（即选最冷的号）
    约束（可选，来自用户偏好）：
      - sum_val 在 [80, 140]
      - odd_count 在 [2, 4]
      - consecutive_count ≤ 2
      - 避免全在 1-31（生日区）
    """
    def objective(indices):
        selected = np.argsort(indices)[:red_count]
        score = popularity_scores[selected].mean()
        # 惩罚违反约束
        penalty = 0
        if constraints:
            if not (80 <= selected.sum() <= 140):
                penalty += 10
            # ... 其他约束
        return score + penalty

    # 模拟退火搜索（组合空间大，用启发式）
    result = dual_annealing(objective, bounds=[(0, 1)] * red_range)
    selected = np.argsort(result.x)[:red_count]
    return sorted(selected.tolist())
```

> 输出 N 组低热度组合供用户选择，每组附带 EV 估算和"撞号概率"评分。

### 8.4 为什么不做"预测开奖号"模型

项目内置一个 `NullModel` 对比实验：用 XGBoost 预测每个红球是否开出，Walk-forward 回测 100 期，预期 AUC ∈ [0.47, 0.53]，与随机无显著差异。该实验结果在前端"模型实验室"页面公开，作为产品诚信的证明。

### 9.2 回测引擎核心逻辑

```python
# engine.py
class BacktestEngine:
    def __init__(self, lottery_code: str, start_period: str, end_period: str):
        self.draws = load_draws(lottery_code, start_period, end_period)

    def run(self, strategy: BaseStrategy, bets_per_draw: int = 1) -> BacktestResult:
        """
        Walk-forward 回测：
        - 对每期 t，策略只能看到 t 之前的数据（防止未来函数）
        - 策略生成 bets_per_draw 注
        - 与第 t 期开奖结果比对，计算中奖等级和奖金
        """
        total_cost = 0
        total_prize = 0
        hit_records = []

        for i in range(len(self.draws)):
            history = self.draws[:i]          # 仅历史数据
            current = self.draws[i]            # 当期开奖
            bets = strategy.generate(history, bets_per_draw)  # 生成选号
            cost = len(bets) * PRICE_PER_TICKET
            prize = self._calc_prize(bets, current)  # 按彩种规则算奖金
            total_cost += cost
            total_prize += prize
            hit_records.append({
                "period": current["draw_period"],
                "bets": bets,
                "cost": cost,
                "prize": prize,
                "tiers_hit": self._tier_detail(bets, current),
            })

        return BacktestResult(
            strategy_name=strategy.name,
            total_cost=total_cost,
            total_prize=total_prize,
            roi=total_prize / total_cost - 1 if total_cost > 0 else 0,
            hit_records=hit_records,
            metrics=compute_metrics(hit_records),
        )
```

### 9.3 Monte Carlo 模拟

```python
# monte_carlo.py
def monte_carlo_simulation(strategy, n_simulations: int = 10000,
                           n_draws: int = 52) -> dict:
    """
    模拟策略在 n_draws 期内的收益分布：
    - 每期开奖从均匀分布随机抽样
    - 策略选号固定（或按策略逻辑生成）
    - 输出 ROI 分布、VaR、最大回撤、盈利概率
    """
    rois = []
    for _ in range(n_simulations):
        simulated_draws = [generate_random_draw() for _ in range(n_draws)]
        result = run_strategy_on_draws(strategy, simulated_draws)
        rois.append(result.roi)
    return {
        "roi_mean": np.mean(rois),
        "roi_std": np.std(rois),
        "roi_5pct": np.percentile(rois, 5),   # VaR 95%
        "roi_95pct": np.percentile(rois, 95),
        "profit_probability": np.mean(np.array(rois) > 0),
        "max_drawdown_mean": ...,
    }
```

### 9.4 防作弊规则

- **禁止未来函数**：策略生成选号时只能访问当期之前的数据，引擎强制隔离。
- **禁止过拟合调参**：超参数在训练期内确定，测试期固定不调。
- **多重检验校正**：对比 N 个策略时，用 Bonferroni 校正 p 值阈值。
- **最小样本量**：回测期数 ≥ 100 期才输出结论，否则标注"样本不足"。

## 10. 评估指标

### 10.1 预测类指标（用于"模型实验室"展示 ML 无效）

| 指标 | 公式 | 随机基线值 | 说明 |
|---|---|---|---|
| Accuracy | TP+TN / N | ≈ 81.8%（红球 6/33 负类占优） | 高度不平衡，无意义 |
| AUC | ROC 曲线下面积 | 0.5 | 核心指标，>0.55 才可能有信号 |
| Log Loss | -Σ[y log p + (1-y) log(1-p)] | 0.478（= -0.182ln0.182-0.818ln0.818） | 校准度 |
| Brier Score | Σ(p-y)² / N | ≈ 0.149 | 概率预测精度 |
| Calibration Error | Σ |pred_p - actual_freq| | 0（理想） | 概率校准 |

### 10.2 选号 / EV 优化指标（核心业务指标）

| 指标 | 公式 / 定义 | 目标 |
|---|---|---|
| **Expected Payout per Yuan (EPPY)** | Σ P(中奖等级) × E[该级单注奖金] / 2 元 | 相对机选提升 ≥ 5% |
| **撞号规避率** | 1 - (选号组合的平均热度 / 全号码空间平均热度) | ≥ 15% |
| **冷门度得分** | 1 - avg_popularity（0-1，越高越冷） | ≥ 0.6 |
| **约束满足率** | 生成组合中满足用户约束的比例 | 100% |
| **多样性** | N 组输出之间的 Jaccard 距离均值 | ≥ 0.7（避免重复） |

### 10.3 回测指标

| 指标 | 定义 |
|---|---|
| ROI | (总奖金 - 总成本) / 总成本 |
| 命中率（分奖级） | 各奖级中奖注数 / 总投注数 |
| 期望回本周期 | 1 / 头奖命中率（理论值 ≈ 1772 万期，展示用） |
| 最大回撤 | 累计收益曲线最大峰谷差 |
| Sharpe-like 比率 | (策略 ROI - 随机基线 ROI) / ROI 标准差 |
| 超额收益 p 值 | 策略 vs 随机基线的配对 t 检验 p 值 |
| Monte Carlo 盈利概率 | 10000 次模拟中 ROI > 0 的比例 |

### 10.4 系统指标

| 指标 | 目标 |
|---|---|
| API P99 延迟 | < 500ms |
| 选号生成耗时 | < 3s（单组），< 10s（10 组） |
| 数据更新延迟 | 开奖后 < 30min |
| 回测 100 期耗时 | < 10s |

## 16. 项目亮点总结

| # | 亮点 | 说明 |
|---|---|---|
| 1 | **科学诚实** | 明确声明彩票不可预测，内置"ML 无效"实验公开验证，不做虚假承诺。在遍地"预测大师"的市场中，诚信本身就是差异化。 |
| 2 | **真实 α：EV 优化** | 不追求预测开奖号（不可能），而是利用 pari-mutuel 机制的唯一低效性——热门号平分风险——通过冷门号选择提升期望值。这是数学上可证明、可回测的真实优化。 |
| 3 | **完整数据工程链路** | 多源采集 → 清洗质量门 → 特征工程 → 模型训练 → 回测验证 → API 服务，覆盖数据工程师全技能栈，可作为工程作品集。 |
| 4 | **严格回测框架** | Walk-forward + 防未来函数 + Monte Carlo + 多重检验校正 + 最小样本量门控，回测结果可信、可复现、可审计。 |
| 5 | **教育价值** | 用真实数据展示 iid 假设、赌徒谬误、过拟合、p 值操纵等统计学概念，是极佳的"反预测"教学平台。 |
| 6 | **合规先行** | 全链路免责声明、年龄拦截、免费定位、不碰支付，从设计上规避法律风险，可长期运营。 |
| 7 | **可扩展架构** | 彩种插件化（新增彩种只需配置 + 采集器）、策略插件化（新增策略继承基类即可）、前端组件化，后续可快速迭代。 |
| 8 | **7 天可落地** | 从数据到前端到部署的完整 MVP，每天有明确验收标准，工程师可直接按计划执行。 |

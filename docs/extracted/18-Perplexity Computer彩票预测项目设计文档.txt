1. 项目背景
彩票作为一种基于随机数生成的概率游戏，在全球范围内拥有庞大的参与者群体。以中国福利彩票双色球为例，每
期销售量常达数亿元，开奖结果完全独立，每次摇奖服从均匀分布。然而，市场上存在大量所谓「预测软件」，利
用用户对「规律」的心理预期进行营销，其技术实现往往缺乏科学依据。
本项目的出发点是：以工程化、可复现的方式，构建一套完整的彩票数据分析与预测系统。系统不承诺提高中奖概
率，而是通过数据采集、统计分析、机器学习建模、回测验证等完整流程，输出结构化的分析结果与预测建议，同
时以可视化方式展示历史数据的统计特征。项目同时作为数据工程与机器学习工程的综合实践，覆盖从数据管道到
前端展示的全链路。

3. 彩票预测可行性的统计学解释
3.1 彩票的数学本质
以双色球为例：从1-33中选6个红球（不重复），从1-16中选1个蓝球。总组合数为 C(33,6) × 16 = 17,721,088 种。
每种组合出现的概率完全相等，即 P(任一组合) = 1/17,721,088 ≈ 5.64×10⁻⁸。每次摇奖相互独立，历史结果不影
响未来结果——这是彩票预测的根本限制。
3.2 为什么「预测」在严格意义上不可能
彩票摇奖使用物理随机数生成器（如摇号机），其输出近似服从均匀分布。在均匀独立同分布（i.i.d.）假设下，任
何基于历史序列的预测模型都无法获得超过随机猜测的期望收益。这意味着：不存在任何函数  f(history)  →
next_draw 使得 P(f正确) > 1/N（N为组合总数）。
3.3 项目仍然可落地的原因
尽管精确预测不可能，项目仍有科学与工程价值，原因如下：
统计检验：通过卡方检验、游程检验等验证开奖结果的随机性，检测是否存在系统性偏差（如设备磨损导致的非均
匀性）。如果偏差存在，则模型可利用该偏差获得微小优势。
概率优化：不追求「猜中号码」，而是优化选号策略的期望收益结构（如覆盖式选号、组合优化），使中奖分布更
平滑。
数据工程实践：完整的数据管道（ETL→特征→模型→回测→可视化）是数据工程与MLOps的综合训练场。
可视化分析：为用户提供数据驱动的决策辅助工具，替代「拍脑袋」选号，提供信息价值。
教育价值：通过回测结果直观展示「预测无效」的统计证据，具有反赌博教育的公益价值。
3.4 统计检验方案
检验方法 目的 判定标准
卡方拟合优度检验 各号码出现频率是否均匀 p > 0.05 → 不拒绝均匀假设
Kolmogorov-Smirnov检验 号码分布是否服从均匀分布 p > 0.05 → 不拒绝
游程检验 (Runs Test) 序列是否随机（无自相关） p > 0.05 → 序列随机
Ljung-Box Q检验 时间序列是否存在滞后自相关 p > 0.05 → 无显著自相关
Mann-Kendall趋势检验 是否存在长期趋势性变化 p > 0.05 → 无趋势

6. 数据清洗规则
6.1 清洗流程
数据采集后进入清洗管道，按以下规则逐步处理，确保数据质量满足建模要求。
步骤 规则 处理方式 验证
1. 去重 以期号为唯一键 INSERT ON CONFLICT DO NOTHINGCOUNT DISTINCT = COUNT
2. 号码范围校验红球1-33，蓝球1-16 超出范围的记录标记为异常 MIN/MAX校验
3. 号码数量校验红球恰好6个，蓝球恰好1个数量不符则丢弃+告警 数组长度校验
4. 重复号码校验红球不可重复 检测到重复则丢弃+告警 SET长度校验
5. 日期校验 开奖日期为周二/四/日（双色球）非开奖日记录标记异常 WEEKDAY校验
6. 期号连续性 期号应连续递增 检测缺失期号并记录 差分检测
7. 缺失值处理 奖池/销售额可能缺失 NULL保留，统计时排除 IS NULL统计
8. 排序标准化 红球按升序排列存储 INSERT前排序 数组有序校验
9. 类型转换 所有号码转为INTEGER 字符串→整数 类型检查
10. 异常值检测和值/跨度超出3σ 标记但不删除 Z-Score计算
6.2 数据质量监控
每次采集后自动执行数据质量检查脚本，输出质量报告。关键指标包括：数据完整率（目标≥99.5%）、异常记录
数、缺失期号列表、号码分布卡方检验p值。质量报告存入Redis缓存，供Dashboard展示。

def clean_draw_record(record: dict) -> dict | None:
    """清洗单条开奖记录，返回清洗后数据或None（如果无效）。"""
    # 1. 号码范围校验
    red_balls = sorted(record.get('red_balls', []))
    if len(red_balls) != 6:
        logger.warning(f"Red ball count != 6: {record}")
        return None
    if any(b < 1 or b > 33 for b in red_balls):
        logger.warning(f"Red ball out of range: {record}")
        return None
    if len(set(red_balls)) != 6:
        logger.warning(f"Duplicate red balls: {record}")
        return None
    blue_ball = record.get('blue_ball')
    if blue_ball < 1 or blue_ball > 16:
        logger.warning(f"Blue ball out of range: {record}")
        return None
    # 2. 日期校验（双色球：周二、四、日）
    draw_date = record.get('draw_date')
    if draw_date.weekday() not in (1, 3, 6):
        logger.warning(f"Unexpected draw day: {draw_date}")
    # 3. 排序标准化
    record['red_balls'] = red_balls

7.4 AC值与组合特征
AC值（Arithmetic  Complexity）反映号码组合的复杂度。计算方法：取6个红球的所有两两差值，去重后得到不同
差值的数量，AC值 = 不同差值数 - (6-1)。AC值越高，组合越「分散」，通常 AC值≥4 被认为是「非规律性」组合。

class RedFrequencyExtractor(FeatureExtractor):
    name = 'red_frequency'
    window_size = 30
    def extract(self, history: list[dict]) -> np.ndarray:
        freq = np.zeros(33)
        for draw in history[-self.window_size:]:
            for ball in draw['red_balls']:
                freq[ball - 1] += 1
        return freq / self.window_size  # 归一化

8. 模型方案对比
本项目设计4种模型方案进行对比，从简单到复杂，覆盖统计方法与机器学习方法。所有模型输出红球33维概率分
布和蓝球16维概率分布，而非直接输出号码组合。
8.1 模型概览
模型 类型 核心思路 训练数据 推理速度 可解释性

8.2 模型详细方案
方案A：频率统计模型（基线）
最简单的基线模型。统计近N期各号码出现频率，作为该号码下期出现的概率估计。预测时按概率分布加权采样。
该模型的假设是：如果摇奖存在微小偏差（如设备磨损），频率较高的号码可能略高于均匀概率。N为可调参数，
默认取100。
class FrequencyModel:
    def __init__(self, window: int = 100):
        self.window = window
        self.red_freq = np.ones(33) / 33  # 拉普拉斯平滑
        self.blue_freq = np.ones(16) / 16
    def fit(self, history: list[dict]):
        recent = history[-self.window:]
        red_counts = np.ones(33)  # 拉普拉斯平滑
        blue_counts = np.ones(16)
        for draw in recent:
            for b in draw['red_balls']:
                red_counts[b - 1] += 1
            blue_counts[draw['blue_ball'] - 1] += 1
        self.red_freq = red_counts / red_counts.sum()
        self.blue_freq = blue_counts / blue_counts.sum()
    def predict(self) -> dict:
        return {
            'red_probabilities': self.red_freq.tolist(),
            'blue_probabilities': self.blue_freq.tolist(),
        }
    def sample(self) -> dict:
        red = np.random.choice(33, size=6, replace=False, p=self.red_freq) + 1
        blue = np.random.choice(16, p=self.blue_freq) + 1
        return {'red_balls': sorted(red.tolist()), 'blue_ball': int(blue)}

方案C：XGBoost多标签分类器
将红球预测建模为33个二分类问题（每个号码「出现/不出现」），蓝球为16分类问题。使用特征工程模块生成的所
有特征作为输入。XGBoost的优势在于处理表格数据的高效性和可解释性（特征重要性）。训练时使用时间序列交
叉验证，避免数据泄露。
import xgboost as xgb
class XGBoostModel:
    def __init__(self, n_estimators=200, max_depth=6):
        self.red_models = []
        self.blue_model = None
        self.params = {
            'n_estimators': n_estimators,
            'max_depth': max_depth,
            'learning_rate': 0.05,
            'objective': 'binary:logistic',
            'eval_metric': 'logloss',
        }
    def fit(self, X, y_red, y_blue):
        # 红球：33个独立二分类器
        for i in range(33):
            clf = xgb.XGBClassifier(**self.params)
            clf.fit(X, y_red[:, i])
            self.red_models.append(clf)
        # 蓝 ball：16分类
        self.blue_model = xgb.XGBClassifier(
            objective='multi:softprob', num_class=16, **self.params
        )
        self.blue_model.fit(X, y_blue)
    def predict(self, X) -> dict:
        red_probs = np.array([m.predict_proba(X)[0, 1] for m in self.red_models])
        blue_probs = self.blue_model.predict_proba(X)[0]
        return {
            'red_probabilities': red_probs.tolist(),
            'blue_probabilities': blue_probs.tolist(),
        }

9. 回测框架
9.1 回测设计原则
回测是验证模型有效性的核心环节。采用滚动窗口（Walk-Forward）回测方式，严格遵循时间序列回测规范，避免
前视偏差（Look-ahead Bias）和数据泄露。
9.2 回测参数
参数 默认值 说明
初始训练窗口 500期 首次训练使用的历史数据量
滚动步长 1期 每次前进的期数
测试窗口 全部剩余期 回测覆盖的全部预测期
特征窗口 30期 特征计算使用的历史窗口
重训练频率 每50期 每50期重新训练模型
最小测试期数 100期 回测结果至少覆盖100期
9.3 回测流程
def walk_forward_backtest(
    model_class, history: list[dict],
    train_size: int = 500, step: int = 1,
    retrain_every: int = 50, feature_window: int = 30,
) -> list[dict]:
    """
    滚动窗口回测。
    返回每期的预测结果与实际结果对比记录。
    """
    results = []
    last_trained = 0
    model = None
    for i in range(train_size, len(history), step):
        # 判断是否需要重训练
        if i - last_trained >= retrain_every or model is None:
            train_data = history[:i]
            model = model_class()
            model.fit(train_data, feature_window=feature_window)
            last_trained = i
        # 获取特征窗口
        feature_data = history[i - feature_window:i]
        # 预测
        prediction = model.predict(feature_data)
        # 实际结果
        actual = history[i]
        # 计算命中
        hit_red = len(set(prediction.get('red_balls', [])) & set(actual['red_balls']))
        hit_blue = 1 if prediction.get('blue_ball') == actual['blue_ball'] else 0

10.2 随机基线定义
随机基线是评估模型是否有效的参照系。定义如下：红球命中服从超几何分布，参数为  N=33（总数）,  K=6（选号
数）, n=6（开奖数）。期望命中数 E = nK/N = 6×6/33 ≈ 1.09。蓝球命中期望为 1/16 = 6.25%。如果模型在回测中
的表现显著优于随机基线（在统计意义上），需要检查是否存在数据泄露；如果与随机基线无显著差异，说明模型
未能发现有效规律——这是预期结果。

14.1 法律合规
彩票发行与管理受《彩票管理条例》及相关法规约束。本项目仅提供数据分析与统计可视化服务，不涉及彩票销
售、代购或任何资金交易。用户必须自行前往官方渠道购买彩票。系统所有页面须在显著位置展示以下免责声明：
免责声明：本系统提供的分析结果和预测建议仅供参考，不构成任何投注建议或中奖保证。彩票开奖为独立随机事
件，历史数据不代表未来结果。请理性购彩，量力而行。未满18周岁不得购买彩票。 
14.2 风险清单
风险类别 风险描述 影响等级 缓解措施

本项目采集的均为公开可获取的开奖数据，不涉及个人隐私信息。用户使用系统时不收集任何个人身份信息（无注
册/登录要求）。API访问日志仅记录IP和请求路径，保留7天后自动删除。

16. 项目亮点总结
1. 科学严谨的统计检验
集成5种统计检验方法（卡方、KS、游程、Ljung-Box、Mann-Kendall），不仅是「预测」，更是对彩票随机性的
科学验证。回测结果透明展示模型与随机基线的对比，让用户直观理解彩票的数学本质。
2. 完整的MLOps流水线
从数据采集→清洗→特征工程→模型训练→回测→API→可视化，全链路自动化。定时任务覆盖数据更新、特征计
算、模型重训练、回测报告生成，实现端到端MLOps。
3. 多模型对比架构
4种模型（频率统计、马尔可夫、XGBoost、LSTM）统一接口，可插拔式架构。回测框架自动对比所有模型表现，
雷达图可视化多维度评估，为模型选型提供数据支撑。
4. 插件式特征工程
特征提取器采用注册表模式，新增特征只需编写一个Python类并注册。覆盖频率、遗漏、走势、AC值、时序5大特
征族，20+特征维度，可灵活扩展。
5. 专业的可视化系统
12个核心图表覆盖统计分析的所有维度，使用ECharts实现交互式可视化。热力图、雷达图、校准曲线等专业图
表，提供数据探索的完整工具集。
6. 合规与公益设计
内置反赌博教育功能，显著展示免责声明和中奖概率说明。不涉及资金交易，不承诺收益，系统定位清晰为「数据
分析工具」。
7. 7天可交付的MVP
精细到每天的任务分解和里程碑验收标准，2人团队7天完成从零到上线。包含风险应对计划和降级策略，确保交付
确定性。

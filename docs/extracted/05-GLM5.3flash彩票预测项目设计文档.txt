# 彩票预测项目科学实现方案（LottoLab）

**项目设计文档 v1.0**

| 项 | 值 |
|---|---|
| 角色 | 高级数据工程师 / ML工程师 |
| 产品代号 | LottoLab — 彩票数据审计与理性决策支持系统 |
| 技术栈 | Python 3.11 / FastAPI / PostgreSQL 15 / Redis / React 18 / ECharts |
| 交付形态 | Docker Compose 一键部署的全栈 Web 系统 |

---

## 1. 项目背景

- 彩票（双色球、大乐透等）开奖数据公开、历史完整（20年+，3000+期），是极佳的数据工程与统计检验素材。
- 市面大量"AI预测软件"宣称能算出下期号码，本质是过拟合 + 幸存者偏差 + 营销话术。
- 本项目以**数据工程师的标准**做一套完整系统：数据管道 → 数仓 → 统计审计 → 模型 → 回测 → API → 前端，每个环节可量化、可验证。
- 核心立场：**不做"预测下期号码"的伪科学产品，做"审计开奖公平性 + 优化选号期望赔付"的真科学产品。**

## 2. 项目真实目标

分三层，逐层可交付：

| 层 | 目标 | 可量化验收 |
|---|---|---|
| L1 数据层 | 开奖数据 ETL + 数仓 + 开放 API | 3000+期入库，校验通过率 ≥99.5%，T+1 更新 |
| L2 分析层 | 随机性审计 + 分布分析 + 可视化 | 全部统计检验输出 p 值与结论徽章 |
| L3 决策层 | 期望值计算器 + 反热门选号策略 | 条件期望赔付提升率（CEVG）有置信区间 |

**明确的非目标：**

- 不承诺、不暗示提高中奖概率（数学上不可能，见第3节）。
- 不售卖号码，不做付费预测。
- 不诱导购彩；所有页面强制展示负期望提示。

## 3. 彩票预测是否可行的统计学解释

**结论先行：预测开奖不可行；优化选号赔付结构可行。**

### 3.1 为什么不可行

以双色球为例（红球33选6 + 蓝球16选1）：

- 样本空间：C(33,6)×16 = 1,107,568 × 16 = **17,721,088**，头奖概率 ≈ 5.64×10⁻⁸，单次开奖信息熵 ≈ **24.08 bits**。
- 摇奖机是独立同分布过程：`P(下期 | 历史) = P(下期)`。历史序列对未来的**条件互信息为 0 bit**——这不是"模型还不够好"，而是信息论层面的硬约束。
- 任何时序模型（LSTM/Transformer/HMM）的所谓"命中提升"，在严格 walk-forward 回测下都会落入随机基线的置信区间内（第9节专门用实验证明这一点）。
- "冷热号""遗漏回补"是赌徒谬误的工程化包装：无放回抽样每次重新开始，遗漏长度不携带信息。

### 3.2 唯一真实的数学优势在哪

- **中奖概率与选什么号无关；条件赔付与别人选什么号有关。**
- 一等奖/二等奖为浮动奖，按中奖注数分摊。选冷门组合 → 极端情况下独享头奖 → **条件期望赔付更高**。
- 冷门特征：避开 1–31 生日区间偏好（尤其 1–12 月份号）、避开上期开奖号（复投人群）、避开连号与规则图形（1-2-3-4-5-6、对角线）、保留 32/33 这类"无生日语义"的号。
- 预估可提升条件期望赔付 **10%–30%**（视奖池结构），此数字本身由本系统的回测模块验证，不拍脑袋。

**一句话：开奖侧没有信息，选号侧有结构性赔付信息。系统就建在这句话上。**

## 4. 可落地项目定位

产品名：**LottoLab**，三个引擎 + 一个证明系统：

| 模块 | 功能 | 科学依据 |
|---|---|---|
| DataHub | 开奖数据 ETL、数仓、API | 数据工程价值 |
| AuditEngine | 随机性检验（χ²/游程/KS/自相关） | 若摇奖设备有物理偏差，这里能检出——这是审计的真实用途 |
| StrategyLab | 玩家热度估计、EV计算器、反热门选号生成器 | 3.2 节的赔付结构优化 |
| FalsificationLab | 用 LightGBM/LSTM 与随机基线对打，输出"无显著差异"报告 | 负结果也是可交付的科学结论，直接击碎伪科学话术 |

## 5. 数据来源与字段设计

### 5.1 数据来源

- 主源：官方开奖公告页，爬虫拉取（遵守 robots.txt，每期开奖后 T+1 一次，频率 ≤3次/周）。
- 备源：人工导入 CSV 通道 + 抽样交叉校验。
- 数据量：~3000 期 × 单行 <1KB，总量 <100MB，**PostgreSQL 单库绰绰有余，不需要大数据组件**——拒绝过度设计。

### 5.3 关键设计：玩家热度数据从哪来（不爬用户数据）

**用固定奖档注数反推玩家选号分布**——这是本方案最巧的一步：

- 六等奖（中蓝球即中，固定5元）注数 ÷ 总投注注数 = 玩家蓝球命中率的样本估计。玩家若均匀选蓝球，理论值应为 1/16 = 6.25%。**实际历史值长期偏离**，即玩家蓝球分布非均匀的证据。
- 五等奖（4+0 / 3+1，固定10元）注数与理论超几何概率的偏差 → 红球侧玩家分布偏差信号。
- 原理：固定奖档奖金不变，注数只由玩家实际所选号码的分布决定，等价于对玩家总体的一个矩估计采样。

## 6. 数据清洗规则

1. **去重**：`draw_id` 主键 + `ON CONFLICT DO UPDATE` 幂等写入。
2. **范围校验**：红球 1–33 且严格升序唯一；蓝球 1–16；违反直接拒绝入库并告警。
3. **逻辑校验**：`Σ(各档注数 × 单注奖金) ≈ 奖金总额`（误差 <1%）；`注数 × 2元 ≈ sales_amount`（误差 <2%），不符则 `quality_flag=1`。
4. **缺失处理**：奖池/销售额缺失置 NULL，**不插补**；StrategyLab 检测到 NULL 自动降级为无奖池模式。
5. **跨源校验**：每周随机抽 10 期与人工 CSV 比对，不一致即阻断管道。
6. **单位统一**：金额一律元，`DECIMAL(16,2)`；时区 UTC+8。
7. **离群标注**：IsolationForest 对销售额/注数打标，只标注不删除。
8. **审计口径**：质检失败率 >0.5% 触发 PagerDuty 告警。

## 7. 特征工程清单

> 用途划分必须明确：A 组检验**开奖号**（审计随机性），B 组刻画**人群行为**（热度建模），均不用于"预测下期开奖"。

**A 组 · 审计特征（开奖侧）**

- 红球频率计数向量（33维）/ 蓝球频率（16维）
- 和值、跨度（max−min）、奇偶比、大小比（≥17为大）
- AC值（算术复杂度）、连号对数、与上期重号数
- 龙头/凤尾序列、遗漏长度序列（每号）
- 蓝球转移计数矩阵（用于独立性检验）

**B 组 · 热度特征（人群侧）**

- 固定奖档命中率历史序列（六等奖/五等奖注数比）
- 生日区间占比：号码 ∈ 1–31，∈ 1–12 加权更高
- 上期开奖号复投热度（下期销量与上期号的相关性）
- 日期特征：开奖星期、月份、节假日前后
- 规则图形度：连号长度、等差、对角线模式打分

**C 组 · 策略特征**

- 组合热度得分 = w₁·生日占比 + w₂·重号数 + w₃·连号 + w₄·图形度（权重由 B 组数据回归标定）
- 各奖级条件期望赔付（结合奖池、热度分布）

## 8. 模型方案对比

| 方案 | 真实用途 | 优点 | 缺点 | 采纳 |
|---|---|---|---|---|
| 均匀随机基线 | 回测参照系 | 理论最优、零成本 | 无 | ✅ 必选基线 |
| 频率/冷热统计 | 审计可视化 | 可解释 | 无预测力 | ✅ 限审计 |
| χ²/游程/KS/自相关 | 随机性审计 | 检出物理偏差，p值可算 | 假设检验仅此用途 | ✅ AuditEngine |
| HMM | 独立性检验 | 若存在状态依赖可检出 | 独立过程无状态 | ✅ 审计工具 |
| LightGBM（时序特征→下期） | **证伪实验** | 满足"能不能预测"的好奇心 | 无信息增益 | ✅ 对照组 |
| LSTM/Transformer | 证伪压力测试 | 工程完整度展示 | 同上 | ✅ 对照组 |
| Dirichlet-Multinomial 贝叶斯后验 | 玩家红/蓝球分布估计 | 小样本稳健、带置信区间 | 先验敏感 | ✅ PopularityModel |
| HDBSCAN / IsolationForest | 离群标注、组合聚类 | 无监督实用 | — | ✅ 辅助 |

**管线编排：**

1. `AuditEngine`：χ² 拟合优度（红球 df=32，蓝球 df=15）、和值序列游程检验、lag-1..20 自相关 ±1.96/√N 置信带、KS 检验（参考 NIST SP 800-22 频率块检验思想）。
2. `PopularityModel`：以六等奖注数比为主信号，Dirichlet 先验 + Multinomial 似然 → 玩家蓝球分布后验；红球侧用五等奖偏差 + 生日先验修正。
3. `FalsificationLab`：LightGBM 与 LSTM 用滚动窗口做"下期号码出现概率"预测，与随机基线正面对比，**预期且要求结论为"差异不显著"**——显著了反而说明审计模块要报警了。

## 9. 回测框架

- **协议**：严格 walk-forward。训练窗 500 期，测试窗 50 期，滑动步长 50，约 45+ 折；禁止任何 shuffle 与信息泄漏。
- **任务定义**：预测下期红球集合（33个号的二分类打分，取 top-6）。
- **基线**：随机选 6 个红球，理论每期命中数期望 = 6×6/33 ≈ **1.09 个**（超几何分布）。
- **判定**：
  - 模型每期命中红球数均值 vs 1.09，双侧 t 检验 + 95% CI；
  - AUC（下期各号出现概率二分类），理论无信息时应 ≈ 0.50；
  - 多折结果做 Bonferroni 校正，防止 45 折里碰巧出一两个"显著"。
- **策略回测（真正赚钱的部分）**：用 PopularityModel 估计的重号分布，在历史真实奖池结构上回测"反热门选号"的条件期望赔付，输出 CEVG 及置信区间。
- 产物：`backtest_report.json`（每折指标、p值、效应量）+ 图表。

## 10. 评估指标

| 模块 | 指标 | 目标/预期 |
|---|---|---|
| 审计 | χ² p值、游程 p值、最大自相关 | 全部 p>0.05（彩票确实随机则通过） |
| 审计 | 蓝球频率最大偏差 | <3σ |
| 证伪 | 命中均值提升 + 95% CI | CI 覆盖 0（即无预测力，作为结论交付） |
| 证伪 | AUC | 0.48–0.52 |
| 策略 | CEVG（条件期望赔付提升率） | +10%~+30%，CI 下界 >0 |
| 策略 | 头奖平均分摊人数下降率 | >20% |
| 诚实性 | EV 绝对值展示 | 必须为负并强制显示 |
| 系统 | 管道 SLA | 开奖后 T+1 12:00 前入库，成功率 ≥99% |
| 系统 | API p95 延迟 | <200ms |
| 系统 | 核心统计模块单测覆盖率 | ≥80% |

## 11. 可视化设计

技术：ECharts + Plotly（统计图带误差棒）。全部图表 hover 显示 p 值/期望值/样本量。

1. **红球频率热力图**：号码 × 年份，叠加期望频次对照层。
2. **和值时序**：折线 + 移动平均 + ±2σ 均值带（直观看"无规律"）。
3. **遗漏图**：每号当前遗漏 vs 理论均值 2σ 带，附"赌徒谬误"科普浮层。
4. **蓝球频率柱状图**：Beta 后验 95% 置信区间误差棒——这是全站最科学的一张图。
5. **双柱对比**：玩家热度分布（估计值）vs 均匀分布，直观暴露生日偏好。
6. **回测直方图**：模型命中数分布 vs 超几何理论曲线叠加。
7. **CEVG 瀑布图**：反热门策略赔付提升分解。
8. **负 EV 蒙特卡洛模拟器**：模拟 10000 条"每期买 10 元、20 年"财富轨迹，展示破产概率——风险教育的核心交互件。

## 13. 前端页面设计

React 18 + Vite + TypeScript + Tailwind + ECharts，六个页面：

1. **Dashboard**：KPI 卡（总期数、最新一期、审计结论徽章——"✅ 通过随机性检验"或"⚠️ 发现偏差"）。徽章是产品灵魂。
2. **数据浏览**：历史表格，排序/筛选/导出 CSV。
3. **统计分析**：频率/遗漏/形态三个 Tab，图表联动。
4. **审计报告**：检验列表 + p 值进度条 + "这意味着什么"白话解释块。
5. **策略实验室**：EV 计算器 + 反热门生成器 + 负 EV 蒙特卡洛模拟器（第11节第8项）。
6. **回测中心**：模型 vs 基线对比，强制显示结论横幅："预测模型与随机选号无统计显著差异（p=0.xx）"。

全局：暗色模式、移动端响应式、每页页脚固定合规文案（见第14节）。

## 14. 风险与合规说明

1. **数学诚实义务**：任何"预测类"输出强制附带统计结论横幅；产品文案禁止出现"提高中奖率/内幕/必中"表述，上线前合规审查。
2. **负 EV 强制展示**：EV 计算器与策略页首屏固定显示"彩票长期期望为负，本系统不改变这一点，只优化极端情形下的赔付结构"。
3. **法律合规**：仅分析公开开奖数据，不构成购彩建议，不收费售号；页面显著位置展示"理性购彩，未满18周岁禁止购彩"；遵守《彩票管理条例》及属地法规。
4. **爬虫合规**：遵守 robots.txt、低频拉取、不绕过反爬机制、数据标注来源、仅用于分析。
5. **误用风险**：蒙特卡洛模拟器即为此设计——把负 EV 破产概率可视化，是反成瘾工具。
6. **工程风险**：官方页面改版 → 备用 CSV 导入通道 + Schema 告警；回测过拟合假象 → walk-forward + 多重比较校正硬编码在框架里，不可关闭。

## 16. 项目亮点总结

1. **数学上诚实**：明确切分"不可行（预测开奖，互信息=0）"与"可行（审计 + 赔付结构优化）"，工程全部建在可行侧。
2. **负结果也是产品**：FalsificationLab 用严格回测证明"AI预测不如随机"，把证伪本身做成可交付功能，直接反打市面伪科学软件。
3. **无侵入的热度推断**：用固定奖档注数 ÷ 销量反推玩家选号分布，零用户数据成本拿到策略核心信号。
4. **真实可量化的优势**：反热门选号目标 CEVG +10%~30%，带置信区间，且回测验证——这是彩票领域唯一有数学依据的杠杆。
5. **完整工程闭环**：ETL → 数仓 → 统计检验 → 贝叶斯建模 → 回测 → API → 前端 → 部署 → 合规，可直接进简历与面试作品集。
6. **社会责任内嵌**：负 EV 蒙特卡洛模拟器把"长期必亏"可视化，产品自带风险教育属性。

**一句话总结**：开奖没有规律，但人有规律；这个系统审计前者，利用后者，并把"无法预测"本身做成一个可量化交付的科学结论。

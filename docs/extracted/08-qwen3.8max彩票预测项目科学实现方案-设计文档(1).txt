# 彩票预测项目的科学实现方案

> 项目代号：**LotteryLab**
> 文档版本：v1.0
> 角色视角：高级数据工程师 / 机器学习工程师
> 文档性质：可直接落地开发的项目设计文档

---

## 1. 项目背景

- 彩票（以中国福利彩票双色球、体育彩票大乐透为例）是国内参与人数最多的随机数游戏之一，民间存在大量"预测大师""规律软件"，但绝大多数是伪科学或诈骗。
- 从工程角度看，彩票开奖数据是一个**公开、完整、结构化、带时间戳的随机序列数据集**，是练习数据管道、统计检验、时序建模、回测框架的优质素材。
- 业界缺少一个**诚实、透明、可复现**的彩票数据分析项目：既完整走一遍 ML 工程链路（采集→清洗→特征→建模→回测→可视化→API→前端），又用严格的统计检验告诉用户"什么能预测、什么不能预测"。
- 本项目定位：**不做骗人的预测软件，做一套完整的随机序列分析系统 + 统计素养教育产品**，同时作为全栈 ML 工程能力的展示载体。

## 2. 项目真实目标

**主目标（工程目标）：**

1. 搭建一条端到端的数据工程管道：定时采集 → 清洗入库 → 特征生成 → 模型训练 → 回测评估 → API 服务 → 前端可视化。
2. 用严格的统计检验（随机性检验、假设检验、置换检验）量化回答："历史开奖数据中是否存在可被模型利用的非随机结构？"
3. 建立一套**诚实的回测与评估框架**：任何"预测策略"必须与随机基线（等概率选号）对比，用统计显著性说话，杜绝过拟合自欺。

**副目标（产品目标）：**

4. 提供一个数据分析型 Web 产品：开奖查询、走势图、遗漏/冷热统计、随机性检验报告、模拟选号（娱乐性质，明确标注不构成预测）。
5. 输出一份公开可复现的《彩票随机性研究报告》，作为项目的科学与合规护城河。

**明确的非目标：**

- ❌ 不承诺提高中奖概率（数学上不可能，见第 3 节）。
- ❌ 不做付费荐号、会员预测等灰色变现。
- ❌ 不引导购彩行为，产品内所有"推荐号码"功能必须标注"随机生成，仅供娱乐"。

## 3. 彩票预测是否可行的统计学解释

这一节是项目的科学基石，前端要以"研究报告"形式向用户展示。

### 3.1 摇奖机制的独立性

- 双色球/大乐透使用物理摇奖机，每期开奖在机制上是**独立同分布（i.i.d.）的均匀采样**：每个号码组合的出现概率恒定。
- 双色球头奖概率 = 1 / C(33,6)×16 = **1 / 17,721,088**；大乐透头奖 = 1 / (C(35,5)×C(12,2)) = **1 / 21,425,712**。
- 独立性意味着：P(本期号码 | 历史所有期) = P(本期号码)。历史数据对下一期**不提供任何信息增益**，互信息 I(X_past; X_next) ≈ 0。

### 3.2 为什么"冷热号""遗漏值"是赌徒谬误

- "某号码 30 期未出，该出了"——这是经典的 **Gambler's Fallacy**。对无记忆过程，遗漏长度服从几何分布：P(遗漏 ≥ k) = (1-p)^k，遗漏多久都不改变下一期概率。
- 冷热号现象是**小样本波动的必然结果**：33 选 6 的均匀采样，在几百期尺度上，各号码出现频次天然存在 χ² 分布范围内的差异，这不是"规律"，是噪声。

### 3.3 可证伪的检验方案（本项目将实际执行）

| 检验 | 方法 | 原假设 H₀ | 判定 |
|---|---|---|---|
| 频率均匀性 | χ² 拟合优度检验 | 各号码等概率 | p < 0.01 才拒绝 |
| 序列独立性 | 游程检验、Ljung-Box 检验 | 序列无自相关 | p < 0.01 才拒绝 |
| 遗漏分布 | KS 检验 vs 几何分布 | 遗漏服从几何分布 | p < 0.01 才拒绝 |
| 可预测性 | 置换检验：模型命中率 vs 随机基线 | 模型无优势 | 置换 10,000 次，模型排名进前 1% 才算显著 |
| 多重比较校正 | Bonferroni / FDR | — | 防止"测 100 个指标总有 5 个显著"的假阳性 |

**预期结论（并已多次被公开研究验证）：** 官方彩票数据通过全部随机性检验，不存在可利用的预测结构。本项目的价值在于**用数据把这个结论跑出来、展示出来**。

### 3.4 唯一真实的"非随机"环节

奖池分配是确定性的：**当出现头奖多注均分时，单注期望收益下降**。避开"大众号码"（生日号 1–31、连号、等差数列）不提高中奖概率，但**提高中奖后的期望奖金**（减少均分人数）。这是全项目唯一有统计学依据的策略性结论，将在前端明确展示。

## 4. 可落地项目定位

**产品定位：** 彩票数据科学分析平台（Lottery Data Science Platform）

一句话：**"用严肃的统计方法研究彩票，用诚实的结论教育用户，用完整的工程链路展示能力。"**

功能矩阵：

| 数据中心 | 历史开奖查询、开奖日历、数据导出 | 事实数据 |

## 5. 数据来源与字段设计

### 5.1 数据来源

| 来源 | 说明 | 优先级 |
|---|---|---|
| 中国福彩网官方开奖公告（www.cwl.gov.cn） | 权威源，HTML 接口 | 主源 |
| 中国体彩网（www.lottery.gov.cn） | 权威源 | 主源 |
| 500.com / 新浪彩票历史数据页 | 结构规整，适合补历史全量 | 备源/冷启动 |
| 手工 CSV 导入 | 兜底 | 备源 |

采集策略：**双源交叉校验**——主源与备源数据逐期比对，不一致则告警并进入人工审核队列。历史冷启动一次性导入全量（双色球 2003 年至今、大乐透 2007 年至今）。

### 5.2 核心表设计（PostgreSQL）

```sql
-- 彩种表
CREATE TABLE lottery_type (
    id            VARCHAR(16) PRIMARY KEY,      -- 'ssq' 双色球 / 'dlt' 大乐透
    name          VARCHAR(64) NOT NULL,
    red_max       SMALLINT NOT NULL,            -- 红球池上限 (33/35)
    red_pick      SMALLINT NOT NULL,            -- 红球选几个 (6/5)
    blue_max      SMALLINT NOT NULL,            -- 蓝球池上限 (16/12)
    blue_pick     SMALLINT NOT NULL,            -- 蓝球选几个 (1/2)
    draw_days     SMALLINT[] NOT NULL           -- 每周开奖日 [2,4,7]
);

-- 开奖记录表（事实表）
CREATE TABLE draw (
    id             BIGSERIAL PRIMARY KEY,
    lottery_id     VARCHAR(16) NOT NULL REFERENCES lottery_type(id),
    issue_no       VARCHAR(16) NOT NULL,        -- 期号 '2026103'
    draw_date      DATE NOT NULL,
    red_balls      SMALLINT[] NOT NULL,         -- 升序 [3,11,17,22,28,30]
    blue_balls     SMALLINT[] NOT NULL,         -- [9]
    pool_amount    BIGINT,                      -- 奖池滚存(分)
    first_prize_cnt INT,                        -- 一等奖注数
    first_prize_amt BIGINT,                     -- 一等奖单注奖金(分)
    total_sales    BIGINT,                      -- 当期销量(分)
    source         VARCHAR(32) NOT NULL,        -- 数据来源
    verified       BOOLEAN DEFAULT FALSE,       -- 双源校验通过
    created_at     TIMESTAMPTZ DEFAULT now(),
    UNIQUE (lottery_id, issue_no)
);
CREATE INDEX idx_draw_date ON draw (lottery_id, draw_date DESC);

-- 特征快照表（按期物化，避免查询时重算）
CREATE TABLE draw_feature (
    draw_id        BIGINT PRIMARY KEY REFERENCES draw(id),
    features       JSONB NOT NULL               -- 见第7节特征清单
);

-- 模型回测记录表
CREATE TABLE backtest_run (
    id             BIGSERIAL PRIMARY KEY,
    model_name     VARCHAR(64) NOT NULL,
    model_version  VARCHAR(32) NOT NULL,
    lottery_id     VARCHAR(16) NOT NULL,
    train_range    DATERANGE NOT NULL,
    test_range     DATERANGE NOT NULL,
    metrics        JSONB NOT NULL,              -- 命中率/logloss/置换检验p值
    params         JSONB NOT NULL,              -- 超参快照
    created_at     TIMESTAMPTZ DEFAULT now()
);

-- 用户表 / 用户选号方案表 / 开奖提醒订阅表（常规字段略，标准设计）
```

金额统一用 `BIGINT` 存"分"，杜绝浮点误差；号码数组存 `SMALLINT[]` 并强制升序（入库前校验）。

## 6. 数据清洗规则

清洗管道（每条规则均有单测覆盖）：

1. **格式规范化**：号码字符串 `"03,11,17"` → `[3,11,17]`；期号统一为 `YYYYNNN` 字符串；日期统一 `Asia/Shanghai` 时区解析。
2. **范围校验**：双色球红球 ∈ [1,33] 且不重复、恰好 6 个；蓝球 ∈ [1,16] 恰好 1 个。大乐透同理。任何越界 → 拒绝入库 + 告警。
3. **去重**：`(lottery_id, issue_no)` 唯一约束；重复抓取时以 `verified=true` 的官方源覆盖备源。
4. **双源一致性校验**：逐期 diff 号码、奖金字段；不一致 → 标记 `verified=false`，进人工审核队列，前端不展示未验证数据。
5. **缺期检测**：按彩种开奖日历生成期望期号序列，diff 实际入库序列，发现缺期自动补抓（最多重试 3 次，指数退避），仍缺则告警。
6. **异常值处理**：`first_prize_amt` 超出 [0, 10亿] 分区间、`total_sales` 为负等 → 隔离到 `draw_quarantine` 表待人工确认，不阻塞主流程。
7. **加开奖/停售期处理**：春节休市等造成的日期跳空是合法的，缺期检测需读取官方休市日历，避免误报。
8. **幂等性**：整个采集任务可安全重跑，upsert 语义，禁止产生重复数据。

## 7. 特征工程清单

按 draw 粒度生成，物化进 `draw_feature.features`（JSONB）。**明确声明：这些特征用于统计描述与模型实验，第 3 节的理论分析预期它们对下一期无预测力，特征的价值在于验证这一点。**

**A. 频次类（滚动窗口 w ∈ {30, 100, 全历史}）**
- 各号码 w 期内出现次数、出现频率、频率 z-score
- 热号 top5 / 冷号 top5（相对全历史期望频率的偏差）

**B. 遗漏类**
- 各号码当前遗漏期数（gap）
- 遗漏值 / 理论平均遗漏比（gap_ratio = gap / (1/p)）
- 历史最大遗漏

**C. 组合形态类**
- 和值（sum）、均值、方差
- 奇偶比（如 4:2）、大小比（以池上限/2 为界）
- 质数个数、连号组数、AC 值（组合复杂度）
- 区间分布（1-11 / 12-22 / 23-33 三区计数）

**D. 时序类**
- 上期和值、上 1/3/5 期和值移动平均
- 与上期相同号码个数（重号数）
- 号码位置一阶差分

**E. 共现类**
- 号码对共现矩阵（33×33 / 35×35），及共现 lift = P(a,b)/(P(a)P(b))
- 共现 lift top-K 号码对

**F. 外部类**
- 奖池金额（对销量有影响，对开奖号码理论上无影响——作为对照特征保留）
- 期序号（年内第几期）、月份、星期

特征全部以 **"截止到第 N-1 期可见"** 为约束生成，杜绝特征穿越（见第 9 节）。

## 8. 模型方案对比

所有模型的输出形式统一为：**对下一期每个号码打分（概率或得分），取 top-K 生成号码组合**。这样保证与随机基线可公平对比。

| 方案 | 思路 | 优点 | 缺点 | 预期结论 |
|---|---|---|---|---|
| **M0 随机基线** | 均匀随机选号 | 数学上就是最优策略 | — | **基准线，预期无法被超越** |
| M1 频率启发式 | 选热号/冷号/遗漏比极端号 | 实现简单，民间流行 | 赌徒谬误，无理论依据 | 命中率 ≈ 基线，用作证伪展示 |
| M2 逻辑回归 | 每号码一个 LR，特征=第7节 A/B/D 类 | 可解释（系数即特征贡献） | 线性假设 | ≈ 基线 |
| M3 XGBoost/LightGBM 多分类 | 33/35 类多标签分类 | 能捕捉非线性交互 | 样本量小（数千期）、极易过拟合 | ≈ 基线，train/test gap 巨大（展示过拟合） |
| M4 LSTM/GRU 序列模型 | 输入近 N 期 one-hot 序列 | 端到端学习时序模式 | 同上，参数量远超信息量 | ≈ 基线 |
| M5 N-gram / 马尔可夫链 | 统计转移概率 | 经典序列方法 | i.i.d. 过程无转移结构 | ≈ 基线 |
| **M6 期望奖金优化器** | 不改中奖概率，优化"避开大众号码"以最大化中奖后的期望单注奖金 | **唯一有真实依据的策略** | 依赖大众选号行为假设 | 展示为项目的科学亮点 |

**实现约定：**
- 框架：Python 3.11 + scikit-learn + LightGBM + PyTorch（M4 可选，V1 可裁剪）。
- 每个模型注册到统一 `ModelRegistry`（model_name, version, hyperparams, artifact path），保证回测可复现。
- M6 实现：维护一份"大众偏好号码权重表"（生日号 1–31 加权、连号/等差加权，权重来自公开的销量结构研究与合理假设，参数可调），选号 = 最大化 E[奖金] = P(中奖) × E[1/均分注数]，在约束下用贪心/模拟退火搜索。

## 9. 回测框架

回测框架是本项目的工程核心，设计原则：**时间旅行不可能、结果可复现、基线永远在场。**

### 9.1 架构

```
BacktestEngine
├── DataSplitter        # 滚动窗口切分，严格按时间
├── FeaturePipeline     # 只用 t-1 及之前数据生成 t 期特征（防穿越）
├── ModelRunner         # 统一 fit / predict_scores 接口
├── BaselineRunner      # M0 随机基线，每组回测跑相同次数
├── MetricCalculator    # 见第10节
├── PermutationTester   # 置换检验：打乱时序重训 1000 次得到零分布
└── ReportWriter        # 结果写入 backtest_run 表 + 生成报告
```

### 9.2 回测协议（硬性规则）

1. **滚动起点回测（walk-forward）**：训练窗 = 前 T 期，预测第 T+1 期，窗口逐期滚动。禁止用未来数据训练。
2. **特征时点约束**：FeaturePipeline 单测中内置"穿越检测"——对任意期 t，断言其可见特征与用全量数据重算的 t-1 截止特征一致。
3. **随机基线对照**：每个模型指标必须与同折同规模基线并列展示；报告禁止只展示模型曲线。
4. **置换检验**：将开奖序列随机打乱后重复完整回测 ≥1000 次，得到零分布；真实模型得分的置换 p 值 < 0.01 才允许在报告中使用"优于随机"字样（预期不会发生，这是诚实机制）。
5. **多重比较**：同时测 N 个模型 × M 个指标时，p 值做 Bonferroni 校正。
6. **可复现**：所有随机种子固定并记录；artifact + 数据快照哈希入库，任意一次 `backtest_run` 可精确重放。
7. **成本护栏**：M4（LSTM）回测单次限制 GPU/CPU 时长，超限自动降采样并在报告中注明。

### 9.3 交付物

每次回测自动生成一份《模型回测报告》：模型 vs 基线对比图、置换检验 p 值、train/test 指标差（过拟合度量）、结论段（自动生成，措辞受 p 值门控）。

## 10. 评估指标

**预测能力类（与基线对比）：**

| 指标 | 定义 | 用途 |
|---|---|---|
| Hit@K（红球命中数） | top-K 选号中命中开奖号的平均个数 | 主指标，直接对标 M0 期望值 K×p |
| Top-N 覆盖率 | 真实号码落入模型打分前 N 名的比例 | 打分质量 |
| Log Loss | 号码级概率的对数损失 | 概率校准 |
| Brier Score | 概率平方误差 | 概率校准 |
| 置换 p 值 | 真实得分在零分布中的分位 | 显著性判定（核心） |
| 中奖模拟器收益 | 用模型选号模拟 10 万期购彩的总盈亏 vs 基线 | 面向用户的直观指标 |

**期望奖金类（M6 专用）：**
- 大众重合度：选号与"大众偏好权重表"top 号码的重合率（越低越好）
- 模拟均分注数与期望单注奖金（基于销量与历史均分数据蒙特卡洛）

**工程质量类：**
- 回测可复现率（重放一致 = 100%）
- 特征穿越检测通过率（必须 100%）
- 数据管道 SLA：开奖后 30 分钟内入库、双源校验通过率 ≥ 99.9%

## 11. 可视化设计

技术栈：ECharts（前端）+ matplotlib（研究报告静态图）。

| 图表 | 类型 | 说明 |
|---|---|---|
| 号码走势图 | 折线/散点矩阵（期号 × 号码） | 经典走势，支持遗漏着色 |

## 16. 项目亮点总结

1. **科学诚实是产品本身**：不是"预测不了就摆烂"，而是把"证明预测不了"做成完整的、可交互的、每期自动更新的研究产品——随机性检验仪表盘、置换检验报告、模型 vs 基线排行榜，全网稀缺。
2. **完整且严格的 ML 工程链路**：walk-forward 回测、特征穿越检测、置换检验、多重比较校正、种子固定可复现——每一步都是生产级 ML 工程规范，可直接作为能力证明。
3. **唯一真实的策略亮点（M6）**：用"避开大众号码最大化期望奖金"这一有数学依据的角度，替代伪预测，既满足用户"选号"需求，又完成统计科普。
4. **数据工程扎实**：双源交叉校验、隔离区、缺期自动补抓、幂等采集——数据质量机制达到金融级数据管道标准。
5. **合规护城河**：强制免责声明、无购彩导流、措辞受统计 p 值门控的自动报告，从产品设计层面规避了此类项目最大的法律与道德风险。
6. **教育价值**：模拟购彩破产曲线、赌徒谬误可视化，让产品自带传播点（"我跑了 10 万期模拟，告诉你为什么彩票不能预测"是天然的爆款内容）。

**一句话总结：这个项目的终极交付物不是一个预测模型，而是一套用工程手段把"彩票不可预测"证明给用户看的完整系统——这既是科学上唯一正确的答案，也是工程上最有含金量的做法。**

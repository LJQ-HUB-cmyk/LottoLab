彩票预测项目科学实现方案

项目代号：Lottery-Science
文档版本：v1.0
角色：高级数据工程师 / 机器学习工程师
技术栈：Python 3.11、FastAPI、PostgreSQL/TimescaleDB、Redis、Celery、LightGBM、PyTorch、React、ECharts、Docker Compose

一、项目背景

彩票开奖数据公开、历史长、字段结构化，适合做数据工程与统计建模项目。但民间“预测彩票”大量存在赌徒谬误、过拟合、数据泄漏和幸存者偏差。

本项目不把“预测中奖号码”作为可交付承诺，而是建设一个科学、可复现、合规的彩票数据平台，包含：

1. 多源开奖数据采集与校验
2. 随机性审计与异常检测
3. 特征工程与策略回测
4. 合规随机选号器
5. 风险教育与预算控制

覆盖彩种：
双色球 ssq：红球 1-33 选 6，蓝球 1-16 选 1，组合数 17721088。
大乐透 dlt：前区 1-35 选 5，后区 1-12 选 2，组合数 21425712。
福彩3D fc3d：000-999，组合数 1000。
排列3 pl3：000-999，组合数 1000。
快乐8 kl8：1-80 选 1-10，选 10 组合约 1.65e12。

二、项目真实目标

非目标：
不承诺预测中奖号码。
不承诺提高单注中奖概率。
不承诺正收益。
不提供售彩、代购、兑奖、资金池。
不诱导倍投、追号、借贷购彩。

真实目标：

1. 数据质量目标：开奖数据完整率大于等于 99.9%，多源一致率大于等于 99.99%。
2. 随机性审计：卡方、KS、自相关、游程、熵检验，输出 p 值与置信区间。
3. 策略回测：任何“热号、冷号、遗漏、AI 预测”策略必须与均匀随机基线对比。
4. 合规选号：生成随机组合，支持预算、奇偶、和值、避开热门组合等约束。
5. 风险教育：展示期望收益、返奖率、中奖概率、历史回撤。
6. 工程可复现：数据版本、模型版本、回测版本、随机种子全记录。

核心 KPI：
数据完整率大于等于 99.9%。
多源字段一致率大于等于 99.99%。
样本外 LogLoss 对均匀基线无显著优势。
策略 ROI 对随机基线不显著为正。
风险提示覆盖率 100%。
API P95 延迟小于 300ms。
同 seed 回测同结果。

三、彩票预测是否可行的统计学解释

1. 独立同分布与无记忆性
   设第 t 期开奖结果为 X_t。公平彩票满足：
   X_t 服从 Uniform(Ω)。
   且 P(X_t=x | X_1,X_2,...,X_{t-1}) = P(X_t=x) = 1/|Ω|。
   历史开奖不改变下一期条件概率。过去出现什么号码，不会让某个号码“该出了”。
2. 组合概率
   双色球一等奖：
   P = 1 / (C(33,6) * 16) = 1 / 17721088。
   大乐透一等奖：
   P = 1 / (C(35,5) * C(12,2)) = 1 / 21425712。
   福彩3D、排列3：
   P = 1 / 1000。
3. 信息熵
   双色球组合空间熵约 24.08 bits。
   大乐透组合空间熵约 24.35 bits。
   历史数据不能降低条件熵：
   H(X_t | H_{t-1}) = H(X_t)。
4. 期望收益为负
   彩票返奖率通常低于 100%，即：
   EV = 求和(p_i * prize_i) - cost < 0。
   长期购买，大数定律使实际收益趋近负期望。短期中奖是方差，不是策略能力。
5. 多重比较与过拟合
   如果测试 10000 个策略，总会有少量策略在历史上表现好。这不是预测力，而是多重比较。必须使用样本外 walk-forward、置换检验、Bonferroni / Benjamini-Hochberg FDR、随机基线 1000 次以上模拟。

结论：
彩票中奖号码不可被稳定预测。可行的是数据审计、随机性检验、策略回测证伪、合规随机选号、风险教育、预算控制。

四、可落地项目定位

产品定位：
彩票数据审计与策略回测平台 + 合规随机选号器。

模块划分：

风控合规：预算、频次、风险提示，输出拦截记录、免责声明。

前端：看板、实验室、回测、选号，输出 Web UI。

六、数据清洗规则

R01 期号唯一：lottery_type + issue + version 唯一。
R02 期号连续：缺失期号告警，不自动插值。
R03 号码范围：双色球红 1-33 蓝 1-16；大乐透前 1-35 后 1-12。
R04 号码数量：双色球 6+1；大乐透 5+2。
R05 号码重复：同一注内禁止重复。
R06 号码排序：红/前区升序，蓝/后区升序。
R07 日期时区：统一 Asia/Shanghai，存储 TIMESTAMPTZ。
R08 销售截止：必须早于开奖时间。
R09 金额精度：NUMERIC(20,2)，禁止 float。
R10 多源比对：号码、日期、奖池不一致时进入冲突表。
R11 源哈希：每次抓取保存 raw hash。
R12 文本编码：UTF-8，去除 BOM、全角空格。
R13 异常值：销量/奖池突变大于 5σ 标记，不删除。
R14 未来函数：特征只允许使用 issue 小于当前期的数据。
R15 审计日志：所有修正写入 audit_log，保留 before/after。

冲突处理优先级：
官方源 > 授权 API > 公开数据集 > 手工导入。
多源多数投票。
无法判定则保留多版本并告警。

基础号码特征：

频率与遗漏特征：

转移与共现特征：
markov_1、markov_2、cooccur_matrix、lift、conditional_prob、graph_embedding。

时间与外部特征：
weekday、month、quarter、holiday_flag、issue_gap_days、sales_amount、pool_amount、first_prize_count、payout_ratio、sales_region_ratio。

特征工程约束：
所有滚动特征必须 shift(1)，禁止使用当期开奖结果。

标准化参数只用训练集拟合。
目标编码必须做时间外采样。
特征版本写入 feature_version。

八、模型方案对比

均匀随机基线：无输入，等概率组合，理论正确，作为主基线。
热号/冷号：频率、遗漏，号码评分，易解释，无统计优势，用于回测证伪。
Beta-Binomial：历史计数，后验概率，概率校准，独立假设下趋近均匀，用于随机性审计。
逻辑回归：特征，号码概率，可解释，线性弱，基线模型。
LightGBM/XGBoost：特征，号码概率，强非线性，易过拟合，实验对比。
LSTM/Transformer：序列，下一期概率，序列建模，数据少、无真实信号，研究负结果。
VAE/GAN：历史组合，生成组合，多样性，模式崩溃、不可解释，选号生成实验。
强化学习：状态、预算，购彩动作，预算控制，奖励稀疏、负期望，预算策略研究。
约束满足/组合优化：用户约束，号码组合，合规可控，不提升概率，生产选号器。
随机性审计模型：全历史，p 值、异常，科学，不预测，生产审计。

推荐生产架构：
RandomnessAudit：卡方、KS、自相关、游程、熵。
UniformGenerator：密码学安全随机 secrets。
ConstraintFilter：奇偶、和值、区间、避开热门。
RiskScorer：预算、频次、期望收益提示。
BacktestEngine：所有策略必须与随机基线对比。

模型输出解释：
模型输出号码概率 p_i。若模型有效，应显著优于均匀概率 1/N。实际结果通常与均匀分布无显著差异。若显著偏离，优先检查数据错误、多重比较、数据泄漏、物理偏差、样本不足。

九、回测框架

原则：
严格 walk-forward。
只用过去预测未来。
每期固定预算。
模拟真实奖金规则、税费、多注。
随机种子可复现。
必须包含均匀随机基线。
必须做置换检验。

伪代码：
def walk_forward(data, strategy, start_issue, end_issue, budget, seed):
rng = np.random.default_rng(seed)
equity = []
cash = 0.0
for issue in issues(start_issue, end_issue):
train = data[data.issue < issue]
actual = data[data.issue == issue]
pred = strategy.fit_predict(train, issue)
tickets = strategy.select(pred, budget, rng)
cost = len(tickets) * ticket_price
prize = simulate_prize(tickets, actual)
cash += prize - cost
equity.append({"issue": issue, "cash": cash, "cost": cost, "prize": prize})
return metrics(equity)

基线：
均匀随机单注。
均匀随机多注。
历史热号：近 30 期频率最高。
历史冷号：遗漏最大。
固定号码：生日、幸运数字。
全组合覆盖：仅理论，不现实。

回测输出：
净值曲线。
每期成本、奖金、累计收益。
ROI、期望值、最大回撤。
命中号码个数分布。
与随机基线差异的 p 值。
按彩种、策略、时间段分组。

十、评估指标

统计指标：
卡方统计量：χ² = 求和((O-E)²/E)，目标 p 大于 0.05。
KS 统计量：p 大于 0.05。
自相关：lag 1..10 接近 0。
游程检验：p 大于 0.05。
熵：接近理论熵。
频率偏差：实际频率减理论频率，在置信区间内。

预测指标：
LogLoss。
Brier Score。
校准曲线。
AUC：仅用于二分类实验，不说明中奖。
Top-K 命中。

策略指标：
ROI = (奖金 - 成本) / 成本。
EV：期望收益。
最大回撤。
夏普。
命中分布：0-7 个命中概率。
预算遵守率。
多样性：组合重复率。

显著性：
置换检验：打乱历史顺序 1000 次。
Bonferroni / FDR 校正。
Bootstrap 置信区间。
样本外测试。

工程指标：
数据完整率。
多源一致率。
API P95/P99。
回测任务耗时。
模型训练耗时。
复现成功率。

十六、项目亮点总结

1. 科学诚实：明确彩票不可稳定预测，用统计检验证伪策略。
2. 工程完整：采集、清洗、特征、模型、回测、API、前端、监控全链路。
3. 可复现：数据版本、特征版本、模型版本、回测 seed 全记录。
4. 合规优先：不售彩、不代购、不承诺收益，预算拦截与风险教育。
5. 负结果价值：把“预测无效”转化为随机性审计与数据质量能力。
6. 生产选号器：均匀随机加约束过滤加风险评分，安全可落地。
7. 多源校验：官方源优先，冲突多版本保留，数据质量可追踪。
8. 回测严谨：walk-forward、随机基线、置换检验、FDR 校正。
9. 可视化强：频率、遗漏、校准、净值、回撤、共现网络。
10. 可扩展：支持双色球、大乐透、福彩3D、排列3、快乐8。

最终交付结论：
本项目可以完整开发、上线、演示、回测和审计，但核心结论应保持科学：彩票开奖结果不可被历史数据稳定预测。项目的真实价值在于数据工程、统计审计、策略证伪、合规选号和风险教育。

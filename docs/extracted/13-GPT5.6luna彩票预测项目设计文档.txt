## 2. 项目真实目标

## 3. 彩票预测是否可行的统计学解释

### 3.1 理论模型

以从 `1...N` 中选择 `K` 个不重复号码的乐透型玩法为例，单个组合的理论概率为：

\[
P(\text{某一组合}) = \frac{1}{\binom{N}{K}}
\]

如果存在附加区号码，从 `1...M` 中选择 `J` 个号码，则完整组合概率为：

\[
P(\text{完整组合}) =
\frac{1}{\binom{N}{K}\binom{M}{J}}
\]

在开奖过程独立、公平且规则不变的前提下，历史开奖数据不能稳定改变下一期特定号码的理论概率。

### 3.2 为什么“冷热号”不能直接构成预测优势

某号码长期未出现，称为冷号；近期频繁出现，称为热号。但在独立随机试验中：

- 近期出现频率高，不代表下一期出现概率降低；
- 长期未出现，不代表下一期出现概率升高；
- “该出现了”的直觉属于赌徒谬误；
- 历史频率偏离理论值可能只是有限样本波动。

### 3.3 统计检验方向

项目可以检验“数据是否显著偏离理论分布”，但不能仅凭未拒绝随机性假设证明绝对随机。

建议使用：

- 单号码频数卡方检验；
- 号码位置分布检验；
- 和值分布检验；
- 奇偶比、大小比检验；
- 连号数量分布检验；
- 游程检验；
- 自相关检验；
- Ljung-Box 检验；
- 置换检验；
- 多重假设检验校正；
- 滚动窗口稳定性分析。

### 3.4 统计学结论标准

模型只有在以下条件同时满足时，才可认为存在研究价值：

1. 严格按照开奖时间进行训练和测试；
2. 预测结果优于随机基线；
3. 优势在多个时间窗口中保持；
4. 优势在不同随机种子下保持；
5. 经过多重检验校正；
6. 扣除投注成本后仍然稳定；
7. 不依赖单次大奖或少量异常样本。

实际项目默认结论应是：系统可以发现历史分布、数据质量问题和统计波动，但不能证明下一期号码可以被稳定预测。

## 6. 数据清洗规则

### 6.1 基础校验

- 期号不能为空；
- 期号必须唯一；
- 开奖日期不能为空；
- 开奖日期不得晚于当前系统日期；
- 号码必须为整数；
- 号码必须位于合法范围；
- 主区和附加区号码不得混淆；
- 同一分区内不得重复；
- 号码数组必须排序；
- 期号与日期顺序不能出现明显逆序。

### 6.2 重复与冲突处理

- 使用 `game_code + issue_no` 作为业务唯一键；
- 期号重复但结果一致：保留一条，记录重复日志；
- 期号重复且结果不一致：进入人工审核队列；
- 多来源结果不一致：不直接覆盖，保留所有原始版本；
- 使用 `source_hash` 检测原始页面变化。

### 6.3 缺失值处理

- 开奖号码缺失：禁止进入训练集；
- 销售额缺失：允许进入号码模型，但不得用于销售额分析；
- 奖池缺失：填充为空，不得用 0 代替；
- 日期缺失：进入待审核队列；
- 不能通过规则验证的数据标记为 `invalid`。

### 6.4 防止时间泄漏

特征 `X_t` 只能使用不晚于开奖期 `t-1` 的信息。

禁止使用：

- 当期开奖号码计算出的特征；
- 开奖后发布的奖池信息；
- 未来期号的统计量；
- 使用全量数据计算后再切分的归一化参数；
- 未来数据参与的缺失值填充；
- 未来开奖结果参与的特征筛选。

## 8. 模型方案对比

### 8.1 随机基线

必须实现以下基线：

1. 理论均匀分布；
2. 随机组合；
3. 按历史频率加权的简单模型；
4. 最近窗口频率模型；
5. 只预测和值或奇偶结构的基线。

没有基线，机器学习模型的“准确率”没有解释价值。

### 8.2 统计模型

#### 模型 A：贝叶斯平滑频率模型

对每个号码使用 Beta-Binomial 或 Dirichlet-Multinomial 模型：

\[
p_i = \frac{c_i+\alpha}{n+\alpha+\beta}
\]

适合：

- 估计号码出现概率；
- 处理小样本；
- 输出概率区间；
- 作为可解释模型。

#### 模型 B：指数衰减频率模型

对较近开奖赋予更高权重：

\[
w_t = \exp(-\lambda \Delta t)
\]

适合分析近期分布变化，但不应直接解释为下一期必然优势。

#### 模型 C：隐马尔可夫模型

可将开奖结构划分为若干隐状态，例如：

- 低和值状态；
- 中和值状态；
- 高和值状态；
- 高频连号状态。

该模型用于探索状态变化，不代表能够准确预测具体号码。

### 8.3 机器学习模型

#### 模型 D：Logistic Regression

对每个号码建立二分类模型：

- 标签：该号码下一期是否出现；
- 特征：历史频率、遗漏、和值、窗口统计；
- 输出：号码出现概率。

优点：

- 可解释；
- 训练速度快；
- 适合建立第一个机器学习基线。

#### 模型 E：LightGBM / XGBoost

适合处理：

- 非线性关系；
- 特征交互；
- 混合类型特征；
- 缺失值。

注意：

- 树模型容易过拟合；
- 必须限制树深度；
- 必须使用时间序列验证；
- 必须进行概率校准。

建议参数范围：

```yaml
num_leaves: [7, 15, 31]
max_depth: [3, 5, 7]
learning_rate: [0.01, 0.03, 0.05]
n_estimators: [100, 300, 500]
min_data_in_leaf: [30, 60, 100]
```

#### 模型 F：多标签模型

一次预测多个号码是否出现：

- One-vs-Rest；
- Classifier Chain；
- 多标签神经网络。

适用于联合建模，但需要处理号码不重复和固定数量约束。

#### 模型 G：深度学习模型

可尝试：

- LSTM；
- Temporal Convolution Network；
- Transformer Encoder。

仅建议作为实验模型，不作为 MVP 默认模型。彩票样本量通常不足以支撑复杂深度模型，极易学习到随机噪声。

### 8.4 模型选择原则

默认生产顺序：

1. 均匀随机基线；
2. 历史频率基线；
3. 贝叶斯平滑模型；
4. Logistic Regression；
5. LightGBM；
6. 深度学习实验模型。

只有当复杂模型在多个滚动窗口中稳定超过简单模型，才保留复杂模型。

## 9. 回测框架

### 9.1 数据切分方式

禁止随机切分。使用时间序列滚动回测：

```text
训练集：第 1 期 ~ 第 T 期
验证集：第 T+1 期 ~ 第 T+k 期

训练集：第 1 期 ~ 第 T+k 期
验证集：第 T+k+1 期 ~ 第 T+2k 期
```

### 9.2 推荐回测参数

- 最小训练窗口：200 期；
- 滚动测试窗口：20 期；
- 步长：1 期；
- 最终保留最近 20% 作为完全锁定测试集；
- 每个模型使用相同训练窗口；
- 每个随机基线使用不少于 1000 次模拟。

### 9.3 回测流程

```python
for split in rolling_splits:
    train = data[data.issue_index <= split.train_end]
    valid = data[
        (data.issue_index > split.train_end) &
        (data.issue_index <= split.valid_end)
    ]

    feature_pipeline.fit(train)
    x_train, y_train = feature_pipeline.transform(train)
    x_valid, y_valid = feature_pipeline.transform(valid)

    model.fit(x_train, y_train)
    probability = model.predict_proba(x_valid)

    metrics = evaluate(
        y_true=y_valid,
        y_prob=probability,
        baseline="uniform_random"
    )

    save_backtest_result(metrics)
```

### 9.4 回测注意事项

- 每期只能使用当时可获得的数据；
- 不能在所有历史数据上先做标准化；
- 不能基于最终测试集调参；
- 不能因为单次高命中率更换评估窗口；
- 所有模型必须使用相同的开奖数据；
- 记录代码版本、数据版本、参数和随机种子。

### 9.5 置换检验

对模型结果进行置换检验：

1. 固定特征和回测切分；
2. 随机打乱标签；
3. 重复训练与评估 1000 次；
4. 比较真实指标在置换分布中的位置；
5. 计算经验 p 值；
6. 使用 FDR 或 Bonferroni 进行多重检验校正。

## 10. 评估指标

### 10.1 概率质量指标

- Log Loss；
- Brier Score；
- Ranked Probability Score；
- Expected Calibration Error；
- Reliability Diagram；
- 概率分箱准确率。

### 10.2 排名指标

- Precision@K；
- Recall@K；
- Hit@K；
- NDCG@K；
- MRR；
- 平均真实号码排名；
- 号码进入 Top-K 的比例。

### 10.3 组合指标

- 至少命中 1 个号码的比例；
- 至少命中 2 个号码的比例；
- 主区平均命中数；
- 附加区平均命中数；
- 和值区间覆盖率；
- 奇偶结构命中率；
- 分区结构命中率。

### 10.4 财务模拟指标

财务模拟只用于研究，不代表真实收益：

- 模拟投注成本；
- 模拟奖金；
- 模拟净收益；
- ROI；
- 最大回撤；
- 盈亏波动；
- 破产概率；
- 置信区间。

如开奖规则、奖金分配或税费信息不完整，不得计算收益结论。

### 10.5 模型上线门槛

模型必须同时满足：

- Log Loss 不劣于均匀基线；
- 多个时间窗口有效；
- 置信区间不完全覆盖随机基线；
- 没有明显数据泄漏；
- 概率经过校准；
- 结果可解释；
- 无误导性文案。

如果无法满足，只保留为实验模型。

## 1. 项目背景

彩票开奖结果通常由固定规则、随机抽取和公开开奖流程共同决定。由于彩票开奖数据具有长期、结构化、可量化等特点，适合用于数据工程、统计检验和机器学习实验。

用户经常关注以下问题：

- 哪些号码近期出现频率较高；
- 哪些号码长期没有出现；
- 是否存在连号、重号、奇偶比例等规律；
- 机器学习是否可以预测下一期号码；
- 某种选号策略是否比随机选择更有效。

这些问题可以通过数据分析平台进行实验，但需要区分：

1. 历史数据中是否存在统计波动；
2. 统计波动是否显著；
3. 统计规律是否能够外推到未来；
4. 模型是否真正超过随机基线；
5. 模型是否能够产生稳定、可重复、具有实际价值的预测优势。

项目不能把历史数据中的偶然规律包装成必然规律，也不能把一次或少数几次命中作为模型有效的证据。

本项目建设一个完整的数据与模型实验系统，覆盖：

- 数据采集；

## 2. 项目真实目标

### 2.1 核心目标

项目的真实目标不是“预测中奖号码”，而是建立一个可审计、可复现、无数据泄漏的概率分析平台。

具体目标如下：

1. 建立统一的彩票开奖数据仓库；
2. 对历史开奖数据进行质量检测；
3. 验证历史开奖结果是否明显偏离理论分布；
4. 计算号码频率、遗漏、和值、奇偶比、连号等统计指标；
5. 建立随机基线、统计模型和机器学习模型；
6. 使用严格的时间序列回测评估模型；
7. 判断模型是否稳定超过随机基线；
8. 输出概率排名和不确定性，而不是确定性结论；
9. 为数据工程和机器学习实验提供标准化框架；
10. 控制误导宣传、数据泄漏和合规风险。

### 2.2 不属于项目目标的内容

以下内容不属于项目范围：

- 保证预测下一期中奖号码；
- 保证中奖概率；
- 保证投入产出比；
- 通过“热号”或“冷号”推断下一期必然结果；
- 通过人工智能破解随机开奖机制；
- 通过机器学习保证稳定盈利；
- 提供在线购买彩票入口；
- 代替用户购买彩票；
- 接收用户投注资金；
- 提供资金充值、提现和奖金结算。

### 2.3 项目成功标准

项目应以工程和统计标准评价，而不是以某一期是否命中评价。

建议成功标准如下：

- 数据完整率不低于 99.5%；
- 期号重复率低于 0.1%；
- 关键字段有效率不低于 99.9%；
- 所有特征均通过时间可用性检查；
- 所有回测结果可以复现；
- 所有模型均有随机基线对照；
- 每个模型都有版本号、参数和训练数据范围；
- 预测结果带有概率、不确定性和生成时间；
- 前端没有“保证中奖”等误导性文案。

## 3. 彩票预测是否可行的统计学解释

### 3.1 理论概率模型

假设某种彩票规则为：

- 从 1 到 N 中选择 K 个不重复号码；
- 从 1 到 M 中选择 J 个附加号码。

在所有组合等概率的情况下，某个完整组合的理论概率为：

P（某一完整组合）  
= 1 / [C（N，K） × C（M，J）]

其中，C（N，K）表示从 N 个号码中选择 K 个号码的组合数量。

如果某个玩法为从 1 到 33 中选择 6 个主区号码，从 1 到 16 中选择 1 个附加号码，则完整组合数量为：

C（33，6）×C（16，1）

单个具体组合的理论概率极低。

### 3.2 独立性假设

如果开奖过程满足以下条件：

- 每期开奖使用相同规则；
- 开奖结果之间相互独立；
- 每个合法组合等概率；
- 没有可利用的设备、流程或数据异常；

那么上一期开奖号码不会改变下一期某个号码的理论概率。

例如：

- 某个号码连续出现多次，不代表下一期必然不出现；
- 某个号码长期没有出现，不代表下一期必然出现；
- 某个号码近期频率高，不代表下一期具有确定优势；
- “已经很久没出现，应该轮到它了”属于典型的赌徒谬误。

### 3.3 热号和冷号的统计解释

热号和冷号可以作为描述性统计指标，但不能直接视为有效预测因子。

例如，某号码在最近 50 期出现 12 次，而理论期望可能为 8 次。这可能来自：

- 随机波动；
- 样本量不足；
- 数据采集错误；
- 开奖规则变化；
- 真实但极小的设备偏差；
- 多次检验中偶然出现的异常结果。

只有在长期、多窗口、多种检验方法下都能观察到相同偏离，并且偏离经过显著性和多重检验校正，才值得进一步研究。

### 3.4 可以研究什么

项目可以研究：

- 单号码频率是否符合理论分布；
- 和值分布是否稳定；
- 奇偶比例是否明显偏离理论值；
- 连号出现频率是否异常；
- 号码之间是否存在统计相关性；
- 不同时间窗口的分布是否发生变化；
- 模型概率是否经过良好校准；
- 模型是否超过随机基线。

### 3.5 不能从统计分析中直接推出什么

不能因为发现以下现象，就推出下一期确定结论：

- 某号码长期未出现；
- 某号码近期频繁出现；
- 某种奇偶结构连续出现；
- 某个和值区间近期较少出现；
- 某模型在历史数据中命中过几次；
- 某个模型在单一回测窗口中表现较好。

### 3.6 推荐统计检验

项目建议实现以下统计检验：

1. 单号码频数卡方检验；
2. 理论分布与经验分布比较；
3. 游程检验；
4. 自相关检验；
5. Ljung-Box 检验；
6. 置换检验；
7. 滚动窗口稳定性检验；
8. Kolmogorov-Smirnov 检验；
9. PSI 分布稳定性分析；
10. 多重假设检验校正。

## 6. 数据清洗规则

### 6.1 期号校验

- 期号不能为空；
- 期号只能包含合法字符；
- 同一玩法下期号必须唯一；
- 期号不能重复；
- 期号顺序不能出现无法解释的大幅倒退；
- 期号与开奖日期应保持基本顺序一致。

### 6.2 日期校验

- 开奖日期不能为空；
- 开奖日期必须为合法日期；
- 开奖日期不得晚于系统当前日期；
- 同一玩法同一日期若存在多期开奖，应根据官方规则确认；
- 日期格式统一为 `YYYY-MM-DD`。

### 6.3 号码校验

- 号码必须为整数；
- 号码必须在规则允许范围内；
- 主区号码不得重复；
- 附加区号码不得重复；
- 主区和附加区不能错误合并；
- 号码数组统一升序排列；
- 号码个数必须符合玩法规则。

### 6.4 重复数据处理

情况一：期号相同、号码相同。

处理方式：

- 保留第一条有效记录；
- 记录重复日志；
- 保存所有原始来源。

情况二：期号相同、号码不同。

处理方式：

- 标记为冲突数据；
- 暂不进入训练集；
- 进入人工复核队列；
- 不允许自动覆盖。

### 6.5 缺失值处理

- 开奖号码缺失：不得进入模型训练；
- 期号缺失：不得进入主表；
- 日期缺失：进入人工审核；
- 销售额缺失：保留为空；
- 奖池缺失：保留为空；
- 不允许把未知金额填充为 0；
- 不允许使用未来数据填补历史缺失值。

### 6.6 异常值处理

- 号码超出范围：标记为无效；
- 号码个数不正确：标记为无效；
- 期号与日期冲突：标记为警告；
- 销售额为负数：标记为无效；
- 奖池为负数：标记为无效；
- 解析失败：保留原始数据并记录错误。

### 6.7 数据质量指标

每天生成以下指标：

- 总记录数；
- 有效记录数；
- 无效记录数；
- 缺失期数；
- 重复记录数；
- 冲突记录数；
- 号码范围错误数；
- 日期异常数；
- 数据源变化数；
- 最新数据日期；
- 数据延迟时间。

- 与上一期重复号码数量；

- 当前号码是否连续出现；

### 7.6 号码频率特征

- 近 5 期出现次数；
- 近 10 期出现次数；
- 近 20 期出现次数；
- 近 50 期出现次数；
- 近 100 期出现次数；

- 历史总频率；
- 当前频率与理论频率差值。

### 7.7 遗漏特征

对每个号码计算：

- 距最近一次出现的期数；
- 最大遗漏值；
- 平均遗漏值；
- 当前遗漏值与平均遗漏值的差值；
- 当前遗漏值排名；
- 连续未出现长度。

遗漏特征只能作为历史描述变量，不能直接解释为下一期必然出现概率。

### 7.8 时间窗口特征

所有窗口必须使用目标期之前的数据：

- 过去 5 期统计；
- 过去 10 期统计；
- 过去 20 期统计；
- 过去 50 期统计；
- 过去 100 期统计；
- 指数衰减统计；
- 滚动均值；
- 滚动标准差；
- 滚动分位数。

### 7.9 统计检验特征

- 滚动卡方统计量；
- 自相关系数；
- Ljung-Box 统计量；
- 经验分布与理论分布距离；
- 号码频率偏离值；
- PSI；
- KL 散度；
- Jensen-Shannon 散度。

### 7.10 特征工程禁止事项

禁止使用：

- 当前期开奖号码；
- 未来期开奖号码；
- 开奖后才能知道的奖池数据；
- 全量数据计算得到的归一化参数；
- 使用完整数据集计算的目标编码；
- 使用未来数据计算的缺失值填充结果；
- 通过最终测试集调参。

## 8. 模型方案对比

### 8.1 模型一：均匀随机基线

所有合法号码具有相同概率。

用途：

- 作为理论基线；
- 检验其他模型是否存在增益；
- 生成随机组合；
- 进行模拟分布比较。

该模型不是为了预测，而是为了回答：

> 复杂模型是否真的比随机选择更好？

### 8.2 模型二：历史频率模型

根据历史窗口内的号码出现频率生成概率。

例如：

P（号码 i）  
= 号码 i 在历史窗口出现次数 / 窗口总出现次数

缺点：

- 容易受到短期波动影响；
- 容易被误解为热号预测；
- 不能处理小样本极端频率；
- 不一定优于均匀基线。

### 8.3 模型三：贝叶斯平滑模型

对号码出现概率进行平滑：

P（号码 i）  
= （出现次数 + α）/（总样本量 + α + β）

优点：

- 可以缓解小样本问题；
- 输出更稳定；
- 具有一定解释性；
- 可以输出概率区间。

### 8.4 模型四：Logistic Regression

针对每个号码建立是否出现的二分类模型。

标签：

- 号码在下一期出现：1；
- 号码在下一期未出现：0。

输入特征：

- 历史频率；
- 遗漏值；
- 滚动统计；
- 和值区间；
- 奇偶结构；
- 分区统计；
- 重复号码统计。

优点：

- 速度快；
- 可解释性较好；
- 适合 MVP；
- 便于检查特征方向。

### 8.5 模型五：LightGBM 或 XGBoost

适用于非线性关系和特征交互。

建议限制：

- 树深度不超过 7；
- 叶子数量不超过 31；
- 设置较大的最小叶节点样本数；
- 使用较小学习率；
- 使用时间序列交叉验证；
- 进行概率校准。

推荐初始参数：

```text
learning_rate = 0.03
max_depth = 5
num_leaves = 15
n_estimators = 300
min_data_in_leaf = 60
subsample = 0.8
colsample_bytree = 0.8
```

### 8.6 模型六：隐马尔可夫模型

可以把开奖结构抽象为若干隐状态，例如：

- 低和值状态；
- 中和值状态；
- 高和值状态；
- 高连号状态；
- 低连号状态。

适合用于：

- 探索状态转移；
- 生成结构性分析；
- 研究分布是否存在阶段性变化。

不适合直接宣传为号码预测模型。

### 8.7 模型七：深度学习模型

可选：

- LSTM；
- TCN；
- Transformer；
- 多标签神经网络。

不建议作为首版默认模型，原因包括：

- 数据量通常不足；
- 参数量较大；
- 容易过拟合；
- 解释性较弱；
- 随机数据中的噪声容易被模型记忆。

### 8.8 推荐模型上线顺序

```text
均匀随机基线
    ↓
历史频率基线
    ↓
贝叶斯平滑模型
    ↓
Logistic Regression
    ↓
LightGBM
    ↓
深度学习实验模型
```

只有当复杂模型在多个时间窗口中持续优于简单模型，才允许进入正式实验报告。

## 9. 回测框架

### 9.1 回测原则

回测必须模拟真实预测场景：

> 在某个历史时点，只使用当时已经知道的数据预测下一阶段结果。

不得随机打乱数据后训练和测试。

### 9.2 时间切分方式

示例：

- 训练集：第 1 期至第 500 期；
- 测试集：第 501 期至第 520 期；
- 训练集：第 1 期至第 520 期；
- 测试集：第 521 期至第 540 期；
- 继续向前滚动。

### 9.3 推荐参数

- 最小训练窗口：200 期；
- 测试窗口：20 期；
- 滚动步长：1 期；
- 最终锁定测试集：最近 20% 数据；
- 随机模拟次数：至少 1000 次；
- 每个模型使用相同数据切分；
- 每个模型使用固定随机种子。

### 9.4 回测流程

第一步：按照开奖时间排序。

第二步：确定训练窗口和测试窗口。

第三步：只使用训练窗口拟合特征处理器。

第四步：生成训练集特征。

第五步：训练模型。

第六步：生成测试集概率预测。

第七步：将预测结果与真实开奖结果对比。

第八步：计算指标。

第九步：保存模型、参数、数据版本和指标。

第十步：进入下一个滚动窗口。

### 9.5 回测结果必须保存

每次回测至少保存：

- 实验 ID；
- 模型名称；
- 模型版本；
- 特征版本；
- 训练起始期；
- 训练结束期；
- 测试起始期；
- 测试结束期；
- 随机种子；
- 模型参数；
- 预测概率；
- 实际开奖结果；
- 所有评估指标；
- 代码版本；
- 数据版本；
- 执行时间。

### 9.6 防止回测作弊

禁止：

- 看到测试结果后调整模型参数；
- 根据单一窗口成绩选择模型；
- 随机切分时间序列；
- 使用未来数据做标准化；
- 反复测试直到得到满意结果；
- 只展示表现最好的窗口；
- 删除表现差的回测结果；
- 只报告命中率，不报告概率损失；
- 不报告随机基线。

### 9.7 置换检验

置换检验流程：

1. 固定特征和时间切分；
2. 随机打乱训练标签；
3. 重复训练和回测；
4. 重复至少 1000 次；
5. 得到随机情况下的指标分布；
6. 将真实模型指标放入该分布中比较；
7. 计算经验 p 值；
8. 对多个指标进行多重检验校正。

## 10. 评估指标

### 10.1 概率指标

#### Log Loss

用于评价预测概率质量：

Log Loss 越低越好。

如果模型对错误结果给出极高概率，Log Loss 会显著变差。

#### Brier Score

用于评价二分类概率预测：

Brier Score 越低越好。

#### 校准误差

将预测概率分成多个区间，比较预测概率和真实发生比例。

例如：

- 预测概率 0.1 至 0.2 的样本；
- 实际发生比例是否接近 0.15。

### 10.2 排名指标

- Precision@K；
- Recall@K；
- Hit@K；
- NDCG@K；
- MRR；
- 平均真实号码排名；
- 进入 Top-K 的比例。

### 10.3 号码命中指标

- 主区平均命中数；
- 附加区平均命中数；
- 至少命中 1 个号码比例；
- 至少命中 2 个号码比例；
- 至少命中 3 个号码比例；
- 完整组合命中次数。

完整组合命中次数由于概率极低，不应作为主要模型指标。

### 10.4 结构指标

- 和值区间命中率；
- 奇偶结构命中率；
- 大小结构命中率；
- 连号结构命中率；
- 分区结构命中率；
- 重复号码数量预测误差。

### 10.5 模拟财务指标

如果进行财务模拟，必须明确是模拟，不代表实际收益。

可以计算：

- 模拟投注成本；
- 模拟奖金；
- 模拟净收益；
- ROI；
- 最大回撤；
- 盈亏波动；
- 连续亏损期；
- 破产概率；
- 收益置信区间。

如果没有可靠的奖金分配、税费和奖池数据，不得输出收益结论。

### 10.6 模型判断标准

模型只有在以下条件同时满足时，才可以认为具有研究价值：

1. 多个滚动窗口中表现稳定；
2. 优于均匀随机基线；
3. 优于简单频率基线；
4. 指标置信区间有明显差异；
5. 通过数据泄漏检查；
6. 经过多重检验校正；
7. 概率校准结果合格；
8. 不依赖单次异常结果；
9. 在完全锁定测试集仍保持效果；
10. 结果能够复现。

- “人工智能精准预测”；
- “百分之百命中”；
- “稳赚不赔”；
- “官方内部号码”；
- “独家杀号技术”；
- “保证中一等奖”；
- “历史规律已经破解”；
- “只要按照模型购买就能盈利”；
- “模型已经证明下一期号码”。

推荐使用以下表述：

- “历史数据分析”；
- “概率排序实验”；
- “模型回测结果”；
- “随机基线对比”；
- “统计分布分析”；
- “不确定性分析”。

### 14.3 数据风险

数据风险包括：

- 数据源页面结构变化；
- 数据解析错误；
- 期号错位；
- 日期错位；
- 号码缺失；
- 不同来源结果冲突；
- 历史数据被修订；
- 不同玩法规则混用；
- 数据采集延迟；
- 数据源短期不可用。

控制措施：

- 保存原始数据；
- 保存抓取时间；
- 保存数据源地址；
- 保存原始内容哈希；
- 建立数据版本；
- 建立人工复核流程；
- 对多来源数据进行交叉校验；
- 对异常数据禁止自动进入训练集。

### 14.4 模型风险

主要模型风险：

1. 过拟合；
2. 数据泄漏；
3. 样本量不足；
4. 特征不稳定；
5. 概率未校准；
6. 多重检验产生假阳性；
7. 只展示表现最好的回测窗口；
8. 将相关性误判为因果性；
9. 将随机波动误判为规律；
10. 使用复杂模型掩盖随机结果。

控制措施：

- 使用时间序列切分；
- 保留完全锁定测试集；
- 保存所有实验结果；
- 使用简单模型作为基线；
- 进行置换检验；
- 进行多重检验校正；
- 发布置信区间；
- 发布模型局限性；
- 定期重新评估模型；
- 禁止根据单期结果调整结论。

### 14.5 用户风险

如果系统面向公众，应提供以下提示：

> 彩票开奖结果具有随机性。历史数据、统计规律和机器学习模型均不能保证未来结果。系统输出仅用于数据分析和机器学习实验，不构成购买彩票建议、投资建议、中奖承诺或收益承诺。请理性参与，避免超出个人经济承受能力。

如果系统可能被未成年人访问，应考虑：

- 不提供购买入口；
- 不提供投注金额计算；
- 不提供资金管理工具；
- 不提供刺激性排名；
- 不提供高频投注提醒；
- 增加年龄和风险提示。

### 16.1 科学性

项目不将彩票分析包装为确定性预测，而是从概率、统计检验和模型评估角度进行研究。

核心科学原则：

- 以理论概率作为基线；
- 以随机模型作为对照；
- 使用时间序列回测；
- 防止未来数据泄漏；

# 附录 C：项目最终结论模板

本项目基于历史开奖数据，完成了数据清洗、统计分析、特征工程、模型训练和时间序列回测。

实验结果应按照以下格式总结：

1. 数据覆盖范围：XXXX 年 XX 月至 XXXX 年 XX 月；
2. 数据总期数：XXXX 期；
3. 有效期数：XXXX 期；
4. 数据质量问题：XXXX；
5. 使用模型：随机基线、频率基线、贝叶斯模型、Logistic Regression、LightGBM；
6. 回测方式：滚动时间窗口；
7. 主要评估指标：Log Loss、Brier Score、Top-K 命中率、平均命中数；
8. 最优模型：XXXX；
9. 随机基线对比：XXXX；
10. 结果稳定性：XXXX；
11. 统计显著性：XXXX；
12. 数据泄漏检查：通过或未通过；
13. 模型局限性：XXXX；
14. 最终结论：模型是否在多个时间窗口中稳定超越随机基线；
15. 风险说明：结果不构成中奖承诺、购买彩票建议或收益承诺。

最终结论应优先回答：

> 模型是否在严格、可复现、无数据泄漏的时间序列回测中稳定优于随机基线？

而不是只回答：

> 某一期是否命中了几个号码？

# 结论

彩票预测项目可以作为一个完整的数据工程和机器学习实验项目实施，但其科学目标应是分析随机性、验证模型和研究概率分布，而不是制造确定性中奖承诺。

最合理的第一版实施路线是：

```text
可靠数据
→ 严格清洗
→ 时间安全特征
→ 随机基线
→ 统计模型
→ 机器学习模型
→ 滚动回测
→ 概率评估
→ 可视化展示
→ 风险与合规控制
```

项目的核心价值不是声称“预测彩票”，而是建立一套可以证明模型是否真正超过随机基线的工程系统。
